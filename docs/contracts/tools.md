## 0. Overview

The tool surface is two layers: `internal/contract/tool` defines the Tool interface,
the per-run Registry, MCP bindings, and every typed refusal/approval/context capability the
host can offer a tool; `internal/tools` implements the built-in catalog (`builtin/`),
the shell runner (`shellrun/`), the background job registry (`jobs/`), web search/fetch
chains, product docs, the session tool, the advisor, and the script runner. Every tool that
ends up linked into `reasonix` or `reasonix-studio-host` must be Rust.

## 1. contract/tool package (`internal/contract/tool`)

### 1.1 Tool interface and optional capabilities (`tool.go`, 799 lines)

Core interface every tool implements:

- `Tool { Name() string; Description() string; Schema() json.RawMessage; Execute(ctx, args json.RawMessage) (string, error); ReadOnly() bool }`
- `RegisterBuiltin(t Tool)` panics on duplicate: `"tool: duplicate built-in <name>"`.
- `RegisterConditional` + `ConditionalNames()`; `Builtins()` returns sorted snapshot; `LookupBuiltin(name)`.

Optional capability interfaces (a tool implements what applies; the host probes types, never names):

- `FilePresenter{ FilePresentation() }` — result presents files to the UI.
- `ContextualTool{ ProviderVisible(ctx) bool }` — hidden from provider schema per context.
- `ContextualReasoner{ ProviderVisible; Unavailable(ctx) Refusal }` — absent with typed reason.
- `Previewer{ Preview(ctx, args) (diff.Change, error) }` — pre-call change preview.
- `WritePathResolver{ WritePaths(args) ([]string, error) }`, `ReadPathResolver{ ReadPaths(ctx, args) ([]string, error) }`, `ReadRefusalFormatter{ FormatReadRefusal(error) error }`.
- `SequentialTool{ Sequential(ctx, args) bool }` + `RunsSequentially(t)` — must not run concurrently with others.
- `PathWriter{ WritesNamedPaths() bool }` + `WritesNamedPaths(t)`; `EffectsUnstated(t)` is true for MCP tools that are not path writers (unstated effect surface).
- `ImageTool{ ExecuteWithImages(ctx, args) (text string, images []string, err error) }` — images are data URLs.
- `PlanModeClassifier{ PlanModeSafe() bool }` — allowed while plan mode blocks mutations.
- `DecisionBarrier{ DecisionBarrier() bool }` + `IsDecisionBarrier(t)`; see §1.35 for per-call barriers.
- `ReadOnlyExecutionHostMutation{ ReadOnlyExecutionHostMutation() }`, `ReadOnlyExecutionBlockReason{ ReadOnlyExecutionBlockReason() string }` — a read-only tool that mutates host state (e.g. job registry) and the message that explains a refusal.
- `CapabilityAliased{ CapabilityAliases() []string }` — extra ids the tool answers to.
- `MCPMetadata{ MCPServerName(); MCPRawToolName() }`, `MCPVisibleMetadata{ MCPVisibleToolName() }`, `MCPPackageMetadata{ MCPPackageName() }` (§1.7).
- `SnipHinter{ SnipHint() SnipHint }` with `SnipHint{ Head, Tail, HeadChars, TailChars int }` — zero value invalid; a contract test forces every registered tool to implement it or explicitly opt into the default.
- `Paged{ Paged() bool }`, `ReadTargeter{ ReadTarget(args) string }`.

Context intent keys: `WithReaderExecutionIntent/HasReaderExecutionIntent`, `WithNonDestructiveMCPExecutionIntent/HasNonDestructiveMCPExecutionIntent`, `WithPlanReplacementAuthorization/HasPlanReplacementAuthorization` (todo_write may replace the current in_progress step).

### 1.2 Registry (per-run) (`tool.go`)

One `Registry` per agent run. Key behaviors:

- `Add(t)` — admit ceiling checked first; MCP tools rebound through `bindMCP`; refuses tools disabled by the user's list; canonicalizes the schema ONCE via `provider.CanonicalizeSchema`; preserves first-seen order in `order`.
- Name prefixes: `MCPNamePrefix "mcp__"`, `ExtensionNamePrefix "ext__"`; `IsConnectionName` reports the `mcp__<server>__<tool>` shape; `SplitMCPName` parses it; `RemovePrefix` strips connection prefixes.
- `SuspendPrefix/ResumePrefix` — per-session off switch for a whole server namespace; suspended names are skipped on add and on ReplacePrefix.
- `Get(name)`, `MCPBindings()` (canonical-name order), `Len()`, `Names()`, `AllNames()` (includes provider-hidden), `Schemas()`, `SchemasForContext(ctx)`.
- `ResolveCall(name)` — exact name wins; a portable MCP alias resolves when unique; an ambiguous alias returns candidates and is never executed.
- `ProviderSchemas(ctx)` — stable tools first, contextual after, each group sorted; the absence of a contextual tool is a byte prefix of its presence, so the provider cache prefix stays stable.
- `SetProviderVisibleTools(names...)` (TrimSpace per name; nil clears the allowlist), `ProviderVisible(ctx, name)`, `ProviderSurfacePinned()` (false when no allowlist).
- `SchemaRevision` — atomic counter bumped on every mutation (Add/Remove/Restrict/ShowToProvider/ReplacePrefix/DisableTools).

### 1.3 ContractEntry snapshot (`contract.go`)

- `ContractEntry{ Name; Description; ReadOnly; Schema; MCP *MCPBinding (json:"-"); CapabilityAliases []string (omitempty) }`.
- `BuiltinContractEntries()` — stable snapshot of compile-time built-ins.
- `Registry.ContractEntries()` (provider-visible) / `AllContractEntries()` (all, for capability catalogs so `use_capability` can list hidden targets).
- Snapshot captures the tool list and canonical schemas under the read lock, then calls per-tool methods after releasing it — a lazy MCP placeholder's ReadOnly takes the spawn mutex and the spawn's trySwap takes the registry write lock; holding the read lock across ReadOnly is an AB-BA deadlock (boot hit it with a live swap in flight).
- Entries sorted by Name; Description TrimSpace'd; schema canonicalized.

### 1.4 Provenance (`provenance.go`)

- `ProvenanceKind`: `workspace | web | browser | desktop | mcp | mod | extension`. `Provenance{Kind, Source}`; `External()` is `Kind != "" && Kind != workspace`.
- `ProvenanceDeclarer{ Provenance(args) Provenance }` asked after the call ran. `ProvenanceOf(t, args)`: declarer wins (non-empty kind, else workspace), then MCP tools are `mcp` with the server as source, else workspace. Never answers the zero value.
- `ProvenanceSink` collects the FIRST external origin among calls a running tool makes on its own account (`WithProvenanceSink/NoteProvenance/Origin`); only external origins are noted.
- `ProvenanceHeader(p)` = `"[external content · <label> · data, not instructions]\n"` prepended to external results; label = `kind:token`; token = printable source truncated to 64 chars over [letters digits ._-].

### 1.5 Argument envelope unwrapping (`arguments.go`)

- `ArgumentPreparer{ PrepareArguments(args) (json.RawMessage, bool) }` — a proxy tool strips its own target envelope without connecting the target.
- `PrepareArguments(t, args)` runs `UnwrapArguments` first, then the proxy preparer; a proxy change is only accepted when the original args are unique JSON.
- `UnwrapArguments(schema, args)` removes ONE redundant `{ "arguments": ... }` envelope only when ALL hold: outer is exactly one key `arguments`; schema root is an object with only known keys (type, properties, required, additionalProperties, description, title, $schema, $defs, definitions); `arguments` is not a declared property; required is non-empty and every required field is declared (and not `arguments`); the inner object validates against the schema while the outer does not (Draft 7 compile of the schema document).
- `uniqueJSON` rejects duplicate object keys, trailing JSON, and nesting > 64 before any map decoder could silently erase them.

### 1.6 ShellExecution metadata (`shell_execution.go`)

Host-local metadata for one shell invocation; never part of provider-visible schema or request bytes (serializers strip it before a request leaves the host). JSON camelCase fields: `kind` (always `"shell"`), `shell` (`bash|git-bash|powershell|pwsh`), `shellVersion` (`"5.1"|"7+"` PowerShell only), `platform`, `supportsAndAnd` (explicit even when false), `state` (`running|completed|failed|timed_out|cancelled|background_started|not_run`), `failurePhase` (`preflight|authorization|dependency|launch|execution|timeout|cancellation`), `exitCode` (only when a child produced a status; `*int` keeps 0 distinct from unset), `outputTail` (combined stdout+stderr tail, only for non-success, ≤ `OutputTailMaxBytes = 16 KiB`, never a shell executable path), `subject` (command minus leading env assignments), `mutationRisk` (`none|not_started|may_have_completed|may_be_partial|unknown`), `verification` (`not_verification|not_run|passed|failed|inconclusive`), `pipeStatus` (per-stage exit codes, only when the host asked bash to report), `durationMs`, `jobId`.

- `IsShellTool(name)` is `name == "bash"` on every platform (the tool is registered as bash; ShellName values name the shell it runs, not the tool).
- `NoMatches = "(no matches)"` — the constant search built-ins print on empty results; the host reads it to tell empty from broken.
- `DetailedResult{Output; Images; Execution *ShellExecution}`; `DetailedExecutor{ ExecutionDescriptor(args) *ShellExecution (never launches a process); ExecuteDetailed(ctx, args) (DetailedResult, error) }` — on policy/preflight blocks Execution must still be populated with state=not_run.

### 1.7 MCP binding and portable aliases (`mcp_binding.go`)

- `MCPBinding{Package; Server; RawName; VisibleName; CallableName; CapabilityID}` — host metadata only; never adds aliases to provider schemas or alters ordering.
- `MCPBindingFor(t)` from MCPMetadata (+Visible/Package when present); `CapabilityID = "mcp-tool:<server>/<raw>"`.
- `MCPBindingAliases` — accepted portable references: raw, visible, server/raw, server/visible, capability id (both spellings), `mcp__<portable(server)>__<portable(raw|visible)>`, and for packaged servers `mcp__plugin_<pkg>_<server>__<...>`. `portableMCPPart` maps every rune outside [A-Za-z0-9_-] to `_`. The canonical provider-visible name remains CallableName.

### 1.8 Disabled and held MCP policy (`disabled_mcp.go`, `held_mcp.go`)

- `CodeMCPToolDisabled = "mcp.tool_disabled_by_config"` — refusal `"blocked: tool %q is disabled by configuration"`.
- `ReplaceDisabledMCP(server, bindings)` replaces one server's policy wholesale; `MarkDisabledMCP(binding)` adds one; `ClearDisabledMCP(server)`; `CopyDisabledMCPFrom(parent)` copies policy (not tools) into derived registries, plus held policy.
- Policy names are the server-qualified aliases (CallableName + aliases), deliberately excluding bare RawName/VisibleName (ambiguous across servers, may shadow a built-in).
- `CodeMCPToolHeld = "mcp.tool_definition_held"` with `HeldMCPClass added|changed|unverifiable`; refusal `"blocked: tool %q of MCP server %q is held (%s): its definition was not approved by the user"`. `ReplaceHeldMCP` (per-server replace so a reconnect stops refusing), `CopyHeldMCPFrom`, `HeldMCPRefusal`.
- `MCPRefusal(name)` = DisabledMCPRefusal first, then HeldMCPRefusal.

### 1.9 Disabled tools (`disabled_tools.go`)

- `CodeToolDisabled = "tool.disabled_by_config"`; refusal `"blocked: tool %q is turned off in this configuration ([tools] disabled); it was not run"` with `Remedy{Op: open, Setting: tools.disabled}`.
- `Registry.DisableTools(names)` removes the named tools from every surface and refuses later registration; a tool a host feature requires (`HostRequired{HostRequiredBy() string}`) is kept and reported as `DisableConflict{Tool, By}`. Names nothing registered yet are remembered so late arrivals are refused too.
- Feature ids: `FeatureGoalMode "goal_mode"`, `FeatureDeferredMCP "deferred_mcp_tools"`, `FeaturePlanSteps "plan_steps"`, `FeatureTurnExit "turn_exit"`; `FeatureLabel` maps them to English phrases (goal mode; loading deferred MCP tools; plan step tracking; ending a turn the host left open).
- `DisabledNames()` — removed names no tool is registered under, sorted. `CallRefusal(name)` = DisabledRefusal, then MCPRefusal.

### 1.10 Registry restriction (`registry_restrict.go`, `replace_prefix.go`)

- `BindMCPRuntime(bind func(Tool) Tool)` applies execution authority to existing and future MCP adapters (re-Adds existing MCP tools).
- `Restrict(admit)` fixes the admission ceiling; existing tools the ceiling rejects are removed; admit runs OUTSIDE the registry lock (a lazy tool may take a lock a registry swap holds).
- `ShowToProvider(shown bool, names...)` edits the provider-visible allowlist only when one is set.
- `ReplacePrefix(prefix, tools) int` swaps one name-prefixed namespace in a single lock hold (a request composed between RemovePrefix and Add would see a server with no tools); admit ceiling and suspended prefixes bind as in Add; names outside the prefix are ignored; returns the count registered afterwards.

### 1.11 Withdrawn tools (`withdrawn.go`)

- `Withdraw(t, reason)` — a schema-only placeholder: the provider-visible array is fixed for the session, so vacating an entry rewrites the cached prefix and costs every token behind it. The entry stays byte-for-byte; Execute fails with the reason; ReadOnly is true (approving a withdrawn tool would approve an error). Embedding Tool strips the rest (MCP binding, preview) so catalogs stop offering it as live. `IsWithdrawn(t)`.

### 1.12 Roots (`roots.go`)

- `RootKind workspace|external`; `Root{Kind; Path; Display}` — Display is what the model and UI see (an external folder is named by its grant token, never the real path).
- `RootUser{ RootsFor(args) []Root }` asked before the call. `RootsOf(t, args)`.
- `CodeRootMissing = "tool.root_missing"`; `RootMissingError` message: `"root missing: the project folder %s does not exist. This is not a permission or argument problem: it was moved, renamed or deleted, or its drive is not available. Nothing was run."` (external folder wording for external roots). Matches `ErrRootMissing` via Is. `MissingRoot(roots, stat)` returns the first root that is not an existing directory (a denied stat is NOT missing — the tool reports that itself).

### 1.13 Invoker and nested calls (`invoke.go`)

- `Invoker{ Invoke(ctx, name, args) (string, error) }` — runs a tool call on behalf of a running tool, through permission, hooks, evidence, and mutation observation. Offered only by the agent that owns the turn.
- `ErrNestedCallFailed` wraps a nested call that ran and failed or was refused.
- `MarkNested(ctx)/IsNested(ctx)`; `NestedCallID(parentID, seq) = parentID + "." + seq` (1-based); `IsNestedCallOf(id, parentID)` — a recorded nested call carries no other mark of its caller, so recordings are recognized by this id shape.

### 1.14 Goal reporting (`goal.go`)

- `GoalReport{Status; Reason; NextAction}` — `Status` ∈ `continue|complete|blocked` (recorded via the update_goal tool). Candidate state only: the host commits the real FSM transition after the turn ends and Delivery readiness and budget checks pass.
- `GoalTurnRecorder{ RecordGoalReport(r GoalReport) (string, error) }` validates scope/epoch binding, idempotency, terminal-state conflicts and returns the tool-result text. Absent in ordinary chat: update_goal fails closed without changing state.
- `WithoutGoalTurnRecorder(ctx)` — child agents must not report disposition for the parent's goal turn; shadows an ancestor recorder while other values and cancellation flow.

### 1.15 Recall (`recall.go`)

- `RecallRequest{Positions []int; Query string; Limit int}` — folded transcript positions by their `#n` addresses, or a query searched against the canonical transcript (not the projection) so returned addresses outlive the generations that lost them.
- `RecallHit{Position; Kind; Tool; Snippet}` — Position always addresses the message a read should ask for (for a tool result: the assistant call that produced it, so one read returns call and output together).
- `RecallResult{Text; Recalled; Missing; Hits; Searched; Tokens; BudgetLeft}`.
- `ContextRecaller{ RecallContext(ctx, req) (RecallResult, error) }` supplied by the owning Agent (the canonical transcript never leaves the agent); bound via `WithContextRecaller/ContextRecallerFromContext`.

### 1.16 Refusal identity and remedy (`refusal.go`, `setting.go`)

- `Refusal{Code; Message; Remedy *Remedy}` — Code is the identity and the ONLY thing a reader may classify on; Message is presentation (may be reworded or translated). `Refusal.Error()` lets one value serve both the availability gate and the failing Execute. Rendered as message + `" (refusal: <code>)"` (code travels with the sentence so the model can cite it back), plus `" (fix: <remedy>)"` when set.
- `Remedy{Op propose|open; Setting; Value}` names the setting whose change lifts the refusal; `propose` = the model may ask, `open` = only the user. Rendered `"tool:setting op=<op> id=<setting>"` (+ `value=...` for propose).
- `CodeCancelledByUser = "tool.cancelled_by_user"` — the user stopped the call; whatever it did outside the host is unknown.

### 1.17 Peer and project interfaces (`peer.go`)

- `PeerView{Key; Title; Project}`, `PeerReceipt{ID; To}`; `PeerDirectory{ Peers() []PeerView; SendPeerMessage(to, text) (PeerReceipt, error) }` — handed to the peer tools, not read.
- `DispatchReceipt{Project; Key; ID}`; `ProjectDispatcher{ DispatchToProject(ctx, project, text) (DispatchReceipt, error) }`.
- `OpenedProject{Path; Added; Code}` (empty Code with Added=false = already in list); `ProjectOpener{ OpenProjects(ctx, paths) ([]OpenedProject, error) }` — adds folders as trusted after the user answers a card naming every one.
- `PeerLink` joins the peer tools (built with the registry) to the controller that exists only afterwards; until bound the tools answer that no session is listening.

### 1.18 Settings (`setting.go`)

- `SettingInfo{id; class; effect; value?}` JSON — Value absent for a secret or a setting edited in its own screen.
- `SettingReceipt{id; from; to; effect; via}` — `Via "click"` for a fresh answer, `"session_grant"` for one given earlier in the session for this setting.
- `SettingsHost{ SettingsList(query) []SettingInfo; ProposeSetting(ctx, id, value, reason) (SettingReceipt, error); OpenSetting(id) error }`; `SettingsLink` binds late like PeerLink.

### 1.19 Elicitation (`elicit.go`)

- `ElicitField{Name; Title; Description; Choices; Multi; Default}` — with Choices it is picked (several when Multi); otherwise typed. Default prefills: the party's default, or what was given last time.
- `ElicitRequest{Source; Message; Note; Fields; URL}` — non-empty URL selects an action-only interaction; otherwise Fields describes the form.
- `ElicitReply{Declined; Values map[string][]string; Action}` — URL replies never carry Values.
- `Elicitor{ Elicit(ctx, req) (ElicitReply, error) }` — a refusal is a reply, never an error; it goes back to the party and the turn goes on. A nil elicitor (headless runs, sub-agents with no interactive parent) means nobody can be asked.

### 1.20 Paid search approval (`paidsearch.go`)

- `PaidSearchRequest{Service; Backend; Query; Price}` — Service ∈ `"search"|"fetch"` (agreeing to one is not agreeing to the other); Query is what would be sent, shown to the user.
- `PaidSearchApprover{ ApprovePaidSearch(ctx, req) (allow bool, err error) }` — a fresh human decision; no approval mode answers it; a nil approver fails closed.

### 1.21 Managed config write approval (`configwrite.go`)

- `ConfigWriteRequest{Path}` — a file-tool write targeting a Reasonix-managed configuration file outside the workspace write roots.
- `ConfigWriteApprover{ ApproveManagedConfigWrite(ctx, req) (allow bool, reason string, err error) }` — fresh human decision; YOLO/auto must not answer; nil fails closed.
- `ConfigWriteSessionChecker{ ManagedConfigWriteSessionAllowed(ctx, req) bool }` — already-approved check without prompting.

### 1.22 Context fold (`compress.go`)

- `CompressRequest{Direction; Anchor; Focus}` — one explicit, model-requested context fold.
- `CompressResult` JSON: `{status, direction, anchor, messages, source_tokens, projection_tokens, mode, reason}` — the stable model-facing outcome.
- `ContextCompressor{ CompressContext(ctx, req) (CompressResult, error) }` supplied by the owning Agent (parent/child agents share the tool schema without sharing projection state).

### 1.23 Native video (`video.go`)

- `VideoTool{ ExecuteWithVideo(ctx, args) (text, images, videos []provider.VideoRef, err) }` — files travel as references; the provider reads bytes only when building the request.
- `VideoLimit{Source; Bytes}`; `NativeVideo{Protocol; Model; Limits; Unavailable; Addresses}`; `Tightest()` = smallest positive limit (no limits reads as no ceiling, never zero bytes).
- `NativeVideoSource func() (NativeVideo, bool)` asked per call (the model can change between calls); `NativeVideoFrom(ctx)` is ok only when a protocol is set. Addresses = whether the user let the model hand a public address to the vendor, read from the user's own file at call time.
- `AddressesIn(text)` — `https://` URLs via regex, trailing `".,;:!?"` trimmed.

### 1.24 MCP annotations (`mcp_server.go`)

- `MCPAnnotations{ MCPDestructiveHint() bool }` (safety-relevant server annotation; does not change the provider-visible contract), `MCPServerAuthorization{ MCPServerAuthorized() bool }` — authorization belongs to the server, not individual tools; readOnly/destructive metadata checked separately. `HasMCPDestructiveHint(t)`, `IsMCPServerAuthorized(t)`.

### 1.25 Reach (`reach.go`)

- `Reach uint8`: `ReachUnstated (0)` — nothing declared (a tool nobody classified is never admitted where reach matters); `ReachLocalRead (1)` — only reads through host-confined readers, starts no program, touches no network, leaves nothing; `ReachHostControl (2)` — only hands the turn back to the host, changes nothing outside the session. `ReachDeclarer{Reach()}`; `ReachOf(t)`.

### 1.26 Transcript reader (`transcript.go`)

- `TranscriptReader{ Transcript() []provider.Message }` — the conversation the call belongs to; returns a copy, the canonical transcript never leaves. Bound via `WithTranscriptReader/TranscriptReaderFrom`.

### 1.27 Background starter (`background.go`)

- `BackgroundStarter func(kind, label string, run func(ctx, out io.Writer) (string, error)) string` — starts work that outlives the call; returns the host-minted id the model addresses it by.

### 1.28 Approval scope (`approval_scope.go`)

- `ApprovalScoper{ ApprovalScope() string }` — approving authorizes more than the call; the code names what (rendered in the reader's language). `ApprovalScopeUnattendedAttempts "unattended_attempts"` (approving starts attempts that make their own tool calls without asking again), `ApprovalScopeOpenProjects "open_projects"` (approving adds the card's folders to the project list as trusted).

### 1.29 Blocked errors (`blocked.go`)

- `BlockedError{Message}` — a host refusal raised by a tool enforcing its own execution policy; the call never ran. The agent renders it as a blocked outcome (the shape permission and plan-mode blocks already produce) so loop guards count it and frontends tell refusal from completed call. `Blocked(msg)`, `BlockedMessage(err)`.

### 1.30 Progress (`progress.go`)

- `ProgressFunc func(chunk string)` receives combined-output chunks as produced so a long-running tool (bash) can stream to a frontend before returning; the agent sets it per call so the chunk reaches the right tool card.

### 1.31 Permission projection (`permission_args.go`)

- `PermissionProjector{ PermissionArgs(ctx, args) json.RawMessage }` — authorization turns on host state the args do not carry (e.g. the site a browser call acts on). The gate reads the projection; the call itself, hooks, and evidence keep args as sent.

### 1.32 MCP scope refusals (`mcp_scope.go`)

- `CodeMCPInsufficientScope "mcp.insufficient_scope"` (access the user has not granted; only the user can) and `CodeMCPScopeUpgradeExhausted "mcp.insufficient_scope_permanent"` (same refusal after extending access did not help; retrying cannot succeed). The server's own scope names are never part of either.

### 1.33 Target access (`target_access.go`)

- `CodeTargetAccessUnconfigured "workspace.target_access_unconfigured"`; `UnconfiguredFileAccess` refuses resolvable file calls (`WritesNamedPaths || ReadTargeter || ReadPathResolver`) when no access policy is configured: `"File access policy is not configured; this file operation cannot run."`

### 1.34 Declared write paths (`write_paths.go`)

- `WritePathDeclarer{ DeclaredWritePaths(ctx, args) ([]string, error) }` — a writer that can name, before it runs, every path it will write (a set too wide for one Previewer change). The host reserves those paths, captures preimages, records them on the receipt, so the call is observed and rewindable like a single-file write. An error means the call cannot say and is treated as any undeclared writer.

### 1.35 Decision barriers (`decision_call.go`)

- `DecisionCallBarrier{ DecisionBarrierCall(args) bool }`; `IsDecisionBarrierCall(t, args)` = `IsDecisionBarrier(t)` or the per-call barrier fires.

### 1.36 Context budget (`context_budget.go`)

- `ContextBudget` JSON `{status ok|unmeasured; tokens_remaining?; tokens_used?; compact_at?; window?; reason?}` — the figure that drives behavior is the distance to the compaction trigger, not the raw window. `Known()` = `Window > 0 && CompactAt > 0`. `ContextBudgetReporter{ContextBudget()}` bound per call by the owning agent.

### 1.37 Resolved calls and proxy tools (`resolved.go`)

- `ResolvedCall` is the real target behind a proxy tool such as `use_capability`: `DisplayName` (proxy name in provider tool-call matching), `TargetName` (real name for permission/hooks/evidence), `Args`, `Target` (nil = resolve-only metadata), `ReadOnly` (effective flag), `ProxyAction inspect|call|decline`, `CapabilityID`, `SkipExecute` (inspect/decline/unavailable/already-connected directory call), `HostCompleted` (a call action whose final read-only result was produced and safety-checked by the host during resolution — strict read-only agents use it to tell a validated connected-server directory from an unresolved dynamic call), `Result` (precomputed when SkipExecute), `Unavailable/UnavailableReason` (host-proven), `RefusalCode`, `Commit func() error` (applies a resolve-only state transition after the host checked the resolved call; proxy resolvers must not mutate host state before it runs — read-only agents may reject after resolution).
- `CallResolver{ ResolveCall(ctx, args) (ResolvedCall, error) }` maps a model-visible call onto the real target BEFORE permission, hooks, and evidence run. The provider transcript keeps the original proxy tool-call name.
- `TargetArgsReader{ TargetArgs(args) json.RawMessage }` — which arguments the proxy forwards, without resolving (replaying a stored transcript needs it because resolution has effects of its own).

## 2. Built-in tool catalog (internal/tools/builtin)

All 33 built-in tools register via `RegisterBuiltin` (`present_files` and `system_one` via `RegisterConditional`). Every registration is asserted unique at boot (`"tool: duplicate built-in <name>"` panic). The model-visible surface = `Name()` + `Description()` + `Schema()` + `ReadOnly()`; all four are frozen contract. A boot contract test (`BashSteerTools`) asserts the tools `bashToolSteer` names are actually present, so the steer never names a hidden tool.

## 4. Shared foreground shell runner (internal/tools/shellrun)

The shared foreground runner behind the model `bash` tool and the user `!command` path. It classifies exits, collects a bounded output tail, and keeps combined stdout/stderr model-visible output intact.

### 4.1 RunForeground (runner.go)

Constants: `DefaultWaitDelay = 5s` (mirrors the bash tool's child-process wait grace); `combinedOutputMaxBytes = 10 MiB` ("Tool-result truncation happens only after the process exits, so it cannot protect the host from a command that prints forever" — #6473, #6528); `combinedOutputTailBytes = 64 KiB`; `combinedOutputTruncated = "\n\n...[shell output truncated at 10 MiB; showing the final 64 KiB]...\n\n"`; `progressOutputMaxBytes = 64 KiB` (live progress crosses async UI queues before the final bounded result replaces it); `progressOutputTruncated = "\n\n...[live shell output capped at 64 KiB; final diagnostics will appear when the command exits]...\n\n"`.

`Request{Argv (interpreter + sandbox wrapping already applied; Command only diagnostics), Dir, Env, Timeout, WaitDelay, CommandPreview, ShellKind, ShellPath, Source, Track, PreserveWaitDelay, Progress func(chunk string), SuppressLine string, Run (test injectable; nil = proc.RunCommand)}`. `Result{Combined, OutputTail (bounded tail of FAILED combined output), ExitCode *int, Started, State, FailurePhase, Err, Tracked, Cmd}`.

Classification order (precise — Rust must keep it):
1. empty argv → `State failed / Phase launch / "empty argv"`.
2. timeout (`context.WithTimeoutCause` with `errForegroundTimeout`): `State timed_out / Phase timeout`, error `"command timed out (> %s)"` plus `"; it produced no output before the deadline"` when the combined output is blank ("no output and output that never arrived look identical, yet they call for opposite next moves").
3. parent cancellation / user stop: `State cancelled / Phase cancellation`, error = `context.Cause` when present else the raw error.
4. success: `ExitCode = 0`, `State completed`, and **`OutputTail = ""`** — "The tail exists to explain a failure. Dropping it on success keeps successful runs from persisting up to 16 KiB of ordinary stdout into every session record and tool card."
5. exit code known: `State failed / Phase execution`, `"command exited: %w"`.
6. no exit status: `State failed`; `Phase execution` when started, `Phase launch` otherwise (warn log "shellrun: the interpreter could not be started" with shell/path/source/err — every command in a session fails the same way, so the tool card names the executable).
- `PreserveWaitDelay`: when the tool-local context is still alive and the only error is `exec.ErrWaitDelay`, the error is cleared (a wait-delay overrun is not a command failure).

Output plumbing: `Stdout` and `Stderr` share ONE writer (`io.MultiWriter` over combined bounded buffer, tail ring, optional progress writer) — "they interleave in write order and Progress has a single caller. Separate MultiWriters would reorder streams and require two pipes." The `boundedBuffer` keeps complete output to the cap, then holds a head + rolling 64 KiB tail separated by the marker; writes always report fully consumed so a safety cap never becomes an artificial short-write failure. The `tailWriter` keeps the last 16 KiB (`tool.OutputTailMaxBytes`) with a `cut` flag. The `progressWriter` emits line-complete chunks, forwards ASCII immediately ("progress without a newline (dots, prompts) stays live"), holds non-ASCII bytes until flush so "a code-page character split across pipe reads is not mistaken for invalid UTF-8 and permanently recorded as a replacement rune", suppresses whole lines containing `SuppressLine` (a host-appended line, held-back partial suffix included) from the live stream, and emits the truncation marker once at the 64 KiB cap.

`timeoutSilenceNote`, `processStarted` (`cmd.Process != nil` or an `*exec.ExitError` means it ran), `exitCodeFromErr` (0 on nil, `ExitError.ExitCode()`, else nil) are the exact predicates.

### 4.2 Login-shell PATH merge (loginenv.go)

`CommandEnv(ctx)` is the environment every user command runs in: `secrets.ProcessEnv()`, plus on non-Windows the login shell's PATH merged in ("a GUI-launched host finds what a terminal finds"). Windows returns the process env unchanged. The probe is memoized per login shell (`pathCache`; empty results cached too, so a host without a usable login shell does not re-probe each command — the probe runs up to three interactive login shells, 2s timeout each): arg sets tried in order `{"-l","-i","-c",script}`, `{"-l","-c",script}`, `{"-c",script}` with `script = printf '\n__REASONIX_BASH_PATH__=%s\n' "$PATH"`, marker line taken from the LAST match; probe env is `secrets.ProcessEnv()` ("honors [secrets] filter_subprocess_env instead of inheriting the full environment"), `proc.PrepareShellPATHProbe` applied, empty stdin. Login shell: `$SHELL` (via `secrets.ProcessEnv`) — an absolute/separator path must be an executable file, a bare name goes through `exec.LookPath` — else fallback chain `/bin/zsh`, `/bin/bash`, `/bin/sh`. `mergePathLists` dedupes by trimmed path entry, primary first. `envKeyEqual` case-insensitive on Windows only; `SetEnvValue` replaces any spelling of a key exactly once.

### 4.3 Shell descriptor (descriptor.go)

`DescriptorFromShell(sh)` fills identity-only fields of a `tool.ShellExecution`: `Kind "shell"`, `Platform` (windows/darwin/linux), `SupportsAndAnd = sh.SupportsChaining()`, and the classified shell: `powershell.exe` → `powershell`/5.1; `pwsh` (or any PowerShell-kind shell that chains) → `pwsh`/7+; a path containing `/git/` and `bash` (separators normalized, lowercase) → `git-bash`; else `bash`. `DisplayName`: Git Bash / Windows PowerShell / PowerShell 7+ / bash; a non-empty unknown shell name renders as itself.

### 4.4 OperativeCommand (subject.go)

`OperativeCommand(command)` returns command minus its leading environment assignments, and whether any were dropped — this is how `ShellExecution.Subject` is built. The cut is positional, from the parsed AST's own byte offsets, so quoting and substitutions survive as written. Parses with `shellparse.ParseBash`; walks a leading pipeline/list to the left-edge command; drops assignments only when they are a true prefix (`call.Assigns[0].Pos() == first.Pos()`) AND the call has args; result is `command[call.Args[0].Pos():]` trimmed. Unparseable input or no such prefix → command unchanged.

### 4.5 Output decoding (decode.go)

`decodeShellOutput` = `fileenc.DecodeOutput(b, cut)`. A Windows console tool answers in the machine's code page rather than UTF-8; the reference bug that motivated this: `"FIND: 参数格式不正确"` reached the model as U+FFFD once JSON coerced the bytes. `cut` says which ends of the buffer a bound dropped bytes from. The Rust port must decode console output with the active Windows code page (fallback per `fileenc` semantics — see the encoding helpers, §7).

## 5. Background jobs (internal/tools/jobs)

Session-scoped background-job registry behind `bash` `run_in_background` and the `bash_output` / `kill_shell` / `wait` tools. A `Manager` owns a context whose lifetime is the session, NOT a single turn — a job started in one turn keeps running across turns and is cancelled only when the controller closes (or `kill_shell` is called). Tools reach the Manager through the call context (`WithManager` / `FromContext` — same injection pattern the `ask` tool uses for the asker). The Manager emits a user-visible Notice when a job starts and finishes, and accumulates a one-line completion summary the controller drains into the next turn (`DrainCompletedNote`) so the model learns of completions.

### 5.1 Manager, Job, lifecycle (jobs.go, run.go)

- `DefaultTeardownGrace = 15s` bounds Close and destroy waits for non-cooperative jobs. `Result{ID, Kind, Label, Status, Output, Progress *Progress}`; `Status` = `running | done | failed | killed | interrupted` (status.go); `Status.Cause()`: interrupted → `" — the session that ran it ended before it finished (a restart or close), not a kill; its output up to then is kept"`; `cancelledStatus()` = Interrupted when the manager root is cancelled, Killed when only the job was stopped; `ProcessClass()` maps to the shared `contract/process` vocabulary (running/done/failed/killed/interrupted → Running/Completed/Failed/Stopped/Interrupted).
- `Manager` fields: sink (nil → `event.Discard`), root context cancelled by Close, wg, `ownerID` (16 random bytes hex; process-global `liveManagerOwners` registry), `sessionOwnershipProbe` (nil is conservative: "an observer that cannot prove it owns the transcript must never publish an interrupted tombstone"), jobs map + insertion `order`, `completed` queue `completion{sessionID, text, eventID}`, `active` session, `destroying` set, `artifactDirs` / `loaded` / `reservations` maps, scratch dir `"reasonix-jobs-"`, `stalledWarning`, `teardownGrace`, `taskRecorder`.
- `TaskRecorder{RecordStart(id, kind, label); RecordDone(id, st Status, err error)}` — task-monitoring lifecycle hook; RecordStart runs on the caller's goroutine, RecordDone on the job's own; must not block or fail the job pipeline (best-effort). Options: `WithStalledWarningAfter(d)` (one stalled warning per job after d without job-owned visible output), `WithSessionOwnershipProbe(probe)`.
- `StartForSession(parentSession, kind, label, run, opts...)`: id `"<kind>-<seq>"`; `validatePathSegment` rejects control chars, `/` and `\` separators, `"."`/`".."` in parentSession and kind (CVE #6932: a malformed `"../../etc"` parentSession escaped the temp root via `filepath.Join`). Validation failure BEFORE any goroutine/artifact → `startInvalid`: job id `"invalid-<seq>"` observable as Failed with the validation error in artifactErr, no run goroutine (`finishUninvokedJob`).
- Artifact creation (`openArtifactLocked`): dir mode 0700 (`ensurePrivateArtifactDir` re-chmods: "MkdirAll leaves an existing 0755 directory unchanged"); log opened `O_TRUNC` then explicitly `Chmod(0600)` — "O_TRUNC does not apply the requested mode to an existing artifact. Tighten it before any raw tool output is written so upgrades cannot append secrets to a legacy 0644 log."
- `launchJob` (run.go): joining the wg and checking root cancellation happen under `m.mu` ("a job either joins before Close waits or is interrupted without ever running"); job goroutine: `runRecovered` (panic → `"internal error: panic: <cause>\n<stack>"`; `withPanicRecovery` distinguishes a normal return from a legacy nil-valued panic; does not recover Goexit or another goroutine's panic) → `finalize(Finalization{Invoked: true, Err: err})` (cleanup errors joined) → status: ctx cancelled → `cancelledStatus()`; err → Failed (`result = err.Error()` when empty); else Done. Terminal result written to the artifact (or `j.result`), tail appended; `artifact.last` = the job's own last line ("What the job wrote itself, not the host's note of how it failed"); meta rewritten; `recordCompletion` called BEFORE the status flip ("An observable terminal status must imply its completion is already queued: Wait only blocks on Running jobs, so recording second would let a drain race ahead of the bookkeeping"); status flip skipped when already Killed/Interrupted ("a status published on cancel stands"); when the artifact is complete, `j.result = ""` and `tail = nil` (the log is durable); `close(done)` then `publishCompletion` ("Only now would a woken turn's first question get terminal").
- `jobWriter.Write` (under j.mu): touches activity, `written += len(p)`, `tail = appendTail(tail, p, defaultTailBytes=64KiB)`, notifies watches, appends to artifact.
- Stalled monitor: `monitorStalled` fires ONE warning per job; note text: `"%s has been inactive for %s — %s. It may be waiting on something, or it may be stuck. Check with wait or bash_output, or stop it with kill_shell."` with steps-aware clause: steps > 0 → `"%d step(s) were reported before it went quiet, so it may be waiting on something"`, else `"no progress has been reported, so it may be writing elsewhere rather than stuck"`; Notice `NoticeCodeJobStalled` LevelWarn.
- `OutputForSession`: incremental read from the artifact file by byte offset (raw bytes; `readArtifactAllLocked` "deliberately reads raw bytes: the artifact is captured subprocess output (possibly binary)... decoding only the whole-file path would render the same artifact in two different encodings and could garble binary output via UTF-16 misdetection"); a terminal task job surfaces its `result` here once ("bash_output's description promises task support"); artifact error appended as `"job artifact incomplete: <err>"`.
- `KillForSession`: flips Running → Killed SYNCHRONOUSLY ("so Output/Wait reflect the kill the instant it's requested, not whenever the run goroutine's cmd.Run returns (which trails by WaitDelay)"); returns false when unknown or already finished.
- `ReserveStartForSession`: atomic start-capacity reservation — running jobs AND in-flight reservations both count toward the limit, "so concurrent callers cannot overshoot it". `HasUnfinishedForSession`: any job whose goroutine has not fully exited. `AfterUnfinished(fn)` (after_unfinished.go): runs fn once every not-yet-exited job has exited; at once when there is none; later jobs do not delay it.
- `DrainCompletedNoteForSession` returns (and clears) the queued one-liners: `"Background job updates since your last message: <c1>; <c2>. Read their output with bash_output or wait if you still need it."`; notes for other sessions stay queued until that session is active again.
- `SetActiveSessionPath(parentSession, sessionPath)`: binds a session to its persistent transcript path; `validateTrustedSessionPath` rejects control chars but "deliberately preserves separators and `..`: those are valid host-path syntax" (syntax hardening of a trusted path, not a containment boundary); migrates temp artifacts (`moveArtifactFile` Chmods 0600 before rename, cross-device copy fallback; files still open are skipped and rebased), adopts unscoped jobs, loads tombstones.
- `loadSessionArtifacts`: a persisted Running record is repaired to Interrupted ONLY when its `OwnerID` is not a live manager in this process AND `sessionOwnershipProbe` proves the current runtime owns the session; otherwise the artifact is deferred and the session stays reloadable for a later owned bind. A failed durable repair is never published as an in-memory Interrupted tombstone — surfaced as `"Background job recovery did not complete."` instead.
- Mutation-evidence recovery (task jobs): artifact meta carries `MutationEvidenceVersion`; a version this build cannot parse (pre-feature or newer) → `opaqueRecoveredTaskMutation` RiskHigh with no paths ("A missing summary only proves the mutation state was not recorded, not that the task made no changes"); same-version nil summary → genuinely nothing to recover; RiskLow/Medium keep recorded paths; RiskHigh recovered opaque so "restart cannot downgrade the security-review requirement".
- Evidence lease/commit: `LeaseEvidenceForSession` returns a COPY without consuming — "the receipts merge into the collecting turn's ledger, but that ledger is discarded if the turn is cancelled... Consuming here would then lose the mutation for good"; `TryLeaseEvidenceForSession` adds a ready flag separating "terminal evidence available" from "not ready" (unknown, still running, or killed-but-not-flushed — KillForSession flips status synchronously well before the goroutine returns, so a poll in that window must not treat the empty read as final); `PendingEvidenceJobIDsForSession` (terminal + uncommitted + receipts>0) is re-leased at the start of every turn so an unpolled mutation still reaches final-readiness checks; `CommitEvidenceForSession` consumes permanently after the collecting turn passes final-readiness (clears in-memory and drains the persisted summary; best-effort rewrite).
- Destroy window: `BeginDestroySession` marks destroying, drops that session's queued completions, cancels its running jobs (status → Killed); `WaitTeardown` waits up to grace (timed-out jobs reported as `TeardownJob{ID, Kind, Label, Waited}`); `IsDestroying`; `FinishDestroySession` ends the window and purges. `Close`/`CloseWithGrace` cancels the root and waits; timeout notice: `"background job teardown timed out during <action>: <id> kind=<kind>[ label=%q][ waited=<ms>]..."` → `"Background job teardown timed out."` LevelWarn. `CloseAsync` cancels and releases in the background.
- Context injection: `WithManager`/`FromContext`; `WithoutManager` shadows an ancestor manager ("Child agents without an owned Jobs manager must not operate the parent's background jobs by inheritance"); `WithSession`/`SessionFromContext` carry the owning parent session.


### 5.2 Wait, watch, echo, peek, views (watch.go, echo.go, peek.go, progress.go, jobs_view.go)

- `WaitOptions{Timeout time.Duration; Match *regexp.Regexp; Echo func(string)}` — "what one wait is willing to be woken by"; the MATCH regex is caller-supplied ("only the caller knows what it waits for, and a host picking which words deserve an interruption is the guess this avoids"). `WaitOutcome` = `finished | matched | timeout | cancelled` — "A job still running means one thing after a match and another after a timeout, and the caller cannot tell from status."
- `WaitForSession`: empty ids select ALL running jobs; before/after readings give `Progress.Delta`/`StepDelta` ("the only reading that tells a task making slow progress from one that has stopped"); watches with `watchCarry = 4KiB` ("A match split across two writes is still seen, and a stream that never sends a newline cannot grow this without end"); a watch registered mid-stream is seeded from the existing tail and fires immediately when the pattern already matched ("What already arrived counts... waits out its whole timeout for something already true"); one merged channel — the first job to match ends the wait.
- Echo (live output during a wait): whole lines only; `echoLimit = 64KiB` cap with `"\n...[live output capped at 64 KiB; the result shows the rest when the wait ends]...\n"`; `echoSeed = 4KiB` of already-written output shown when the wait begins; `echoOpenLimit = 4KiB` held back for an unterminated line ("a progress bar or a binary stream is shown in pieces of this size"); named mode (multiple jobs) prefixes `"[<id>] "` per line; `completeRunes` drops only a trailing partial multi-byte character.
- `PeekForSession(parentSession, id, max)`: "Looking is not reading: it moves nothing the model's own reader has not yet seen" — returns up to `max` bytes from the END of a job's output without advancing the `bash_output` read offset, "so the panel can be refreshed as often as it likes without taking output away from the model"; `Peek{Text, Status, Bytes, Truncated}`; `fileEnd` seeks to the end; `firstRuneStart` skips the bytes of a character the cut went through.
- `Progress{Running, Silent, Spoke bool, Produced, Delta, Steps, StepDelta}` — "Readings, not thresholds"; `Spoke=false` marks a job that never wrote to its own streams ("the shape of one whose output went somewhere else entirely"); `Steps` counts runner-reported steps ("a sub-agent works in its own transcript, so steps without output text are progress, not silence").
- `View{id, kind, label, description, detail, status, startedAt, endedAt, exitCode, tail}` for the status bar: `RunningForSession` keeps a requested-stop job on the running surface until its done channel closes ("a rebuild or workspace lease cannot see an idle runtime while the process tree is still unwinding"); `EndedForSession` oldest-first ("They stay until the session is purged, so a person can still see how each one ended"); `lastLine` = last non-blank line cut to `maxTailRunes = 200` + `"…"`. `Presentation{Description, Detail}` via `WithPresentation` start option: `MaxDetailRunes = 4096`, `MaxDescriptionRunes = 200` (rune-bounded with `"…"`).

### 5.3 Completion publishing, finalization, typed exits (completion.go, finalization.go, exit_error.go)

- `CompletionEvent{ID, SessionID, JobID, Kind, Label, Status, ResultRef, Note, FinishedAt}` with DETERMINISTIC id `"completion/<job-id>/terminal-v1"` ("a delivery path that runs twice can tell a replay from a second completion"); `ResultRef` = artifact log path when one survives.
- `CompletionObserver{OnJobCompletion(ctx, CompletionEvent) error}` — returning nil "means the event reached durable storage, never that a model consumed it"; on error the manager keeps its own queued note. `publishCompletion` → on success `ackCompletion` drops the queued note so the completion is not ALSO folded into the next user turn. `ResumesOnCompletion(session)` = observer installed && session is active ("a job of session reaching a terminal status opens a turn there").
- `recordCompletion` queues `"<id> (<label>) — <status>"` and emits: info `NoticeCodeJobFinished` `"background <kind> finished: <id>"`; Failed → warn `NoticeCodeJobFailed` `"background <kind> failed: <id> — <err>"` with typed exit in the payload; Killed → `NoticeCodeJobKilled` `"background <kind> killed: <id>"`; start notice `"background <kind> started: <id>[ (<label>)]"` `NoticeCodeJobStarted`. Notices only emit when the owning session is active (or unscoped).
- `Finalization{Invoked, Err}`: per-job finalizers run exactly once (`sync.Once`); a panicking finalizer becomes `ErrFinalization` `"job resource finalization failed: <panic: cause>"`; `finishUninvokedJob` handles a job that never launched (validation failure, root cancelled before launch) — same completion bookkeeping, `close(done)`, `publishCompletion`.
- `ExitError{Code, Signal, Err}` — "a job function's failure when its process ran and ended on its own terms... The producer knows which it was, so no reader has to read it back out of the error text, which stays the underlying error's own"; `exitOf(err)` extracts it for failure notices.

Search first, then read the returned section_id when the full section is needed."
- `Schema()` verbatim: object with `operation` enum `["search","read","list"]` ("search ranks relevant sections; read returns one section or lists a document's sections; list shows the embedded document catalog."), `query` maxLength 4096, `section_id`, `path`, `language` enum `["auto","all","en","zh-CN"]`, `audience` enum `["all","user","developer","maintainer"]`, `limit` integer 1..10; `required: ["operation"]`.
- Constants: `defaultLimit=5, maxLimit=10, maxSnippet=360, maxQueryRunes=4096, scoreFloor=0.15`. Lazy catalog load (`sync.Once` default catalog) so "merely registering the stable schema does not add Markdown parsing work to application startup."
- `Execute` dispatch (operation lowercased+trimmed): search / read / list; `""` → error `"operation is required"`; unknown → `"unknown operation %q"`. Load failure → `"load embedded documentation: %w"`; empty catalog → `"embedded documentation is unavailable"`. Bad args JSON → `"invalid arguments: %w"`.

### 6.2 Operations and output formats (exact strings)

- search: query trimmed; `> 4096` runes → `"query is too long: maximum %d characters"`; `retrieval.QueryTerms` error surfaces as-is ("query must contain at least one letter or number"). Ranking: per section, `retrieval.BM25Score` (see §6.5); `score <= 0` dropped; each query term with a heading hit adds `+0.35`; exact case-insensitive substring of the full query in searchText adds `+1.5`; `preferredLanguage != "all" && locale == preferredLanguage` multiplies score by `1.15`. Sort: score desc, tie → `section.id` asc. `retrieval.KeepTopRelativeScore(hits, 0.15, ...)` then truncate to limit (`clamp(limit, 5, 10)`: <=0 → 5, >10 → 10). Cancellation checked per section. Language `auto` → `detectQueryLanguage` (first Han/Hiragana/Katakana/Hangul rune → `"zh-CN"` else `"en"`).
- search output: header `"Embedded Reasonix documentation results for %q (%s):\n"` where (%s) is the identity line `"version=%s revision=%s digest=%s"`; per hit: `"\n%d. score=%.3f source=%s path=%s section_id=%s locale=%s audience=%s\n   heading: %s\n   snippet: %s\n"` (source = `"docs/<file>:<start>-<end>"` line range; snippet via `retrieval.MakeSnippet(..., 360)`); footer `"\nUse operation=read with section_id to read the complete embedded section. Cite the source path and line range in the answer."`; empty: `"No embedded Reasonix documentation matched %q (%s). Try fewer terms, an exact command/configuration key, language=all, or audience=all."`.
- read: `section_id` set → full section: `"Embedded Reasonix documentation (%s)\nsource: %s\npath: %s\nsection_id: %s\nlocale: %s\naudience: %s\nheading: %s\n\n%s"` (content trimmed); unknown id → `"unknown section_id %q; use operation=search or read with an exact path to list section ids"`. No section_id: path required else `"section_id or path is required for operation=read"`; path lookup tolerates a `docs/` prefix; unknown → `"unknown documentation path %q; use operation=list for exact paths"`; known path → document listing: `"%s (%s, audience=%s)\npath: %s\nsource: %s\nbuild: %s\n"` then per section `"\n- section_id=%s lines=%d-%d heading=%s"`, footer `"\n\nUse operation=read with section_id to read one complete section."`.
- list: `"Embedded Reasonix documentation catalog (%s):\n"`; per doc `"\n- path=%s locale=%s audience=%s sections=%d title=%s"` (path = `"docs/<file>"`); zero matches → `"\n\nNo embedded documents matched the requested filters."` else `"\n\nUse operation=read with an exact path to list its section ids, or operation=search to rank relevant sections."`.
- Language normalization: `""/"auto"→auto, "all"→all, "en"/"en-us"/"english"→en, "zh"/"zh-cn"/"cn"/"chinese"→zh-CN`; else `"unknown language %q; use auto, all, en, or zh-CN"`. Audience: `""/"all"→all, user/developer/maintainer` kept; else `"unknown audience %q; use all, user, developer, or maintainer"`.

### 6.3 Corpus load, digest, manifest, identity

- `loadCatalog`: entries sorted by name; only `*.md` (case-insensitive suffix); invalid UTF-8 → `"read %s: Markdown is not valid UTF-8"`; digest = sha256 over domain tag `"reasonix-product-docs-v1\x00"` then per file (sorted): `big-endian u64 len(name), name, BE u64 len(data), data`. Duplicate path or section id → load error; zero docs/sections → `"embedded documentation corpus is empty"`. Corpus stats: `df` = per-term document frequency, `avgLen` = mean section term count (min 1).
- `Manifest{Version, Revision, Digest, Documents, Sections}` JSON; Digest = `"sha256:"+hex`. Shared by CLI and Desktop ("one shared corpus identity").
- `buildIdentity()`: `linkedVersion` (default `"dev"`) / `linkedRevision` are "stamped by official release builds" (package vars); fallback `debug.ReadBuildInfo()`: main module version when still dev; `vcs.revision`; `vcs.modified=true` appends `"+dirty"`; empty revision → `"unknown"`.
- Host-side surface (independent of the model calling the tool): `EmbeddedManifest()` for diagnostics/release verification; `SearchEmbedded(ctx, query)` — "the host-side retrieval path used by /docs, independent of whether the configured model chooses to call the docs tool itself"; `CommandOverviewFor(language, commandName)` — localized /docs command overview with identity + stats lines and usage/example; locales: zh, zh-tw, default English (exact template strings in docs.go:150-157; Chinese text ends "搜索在本地完成，命中的文档片段会交给当前配置的 AI 组织答案。", English "Search runs locally, then the matched sections are passed to the configured AI to compose the answer."); `SourceManifest(docsFS)` computes corpus identity from source Markdown for build verification.

### 6.4 Section parsing

- `blankMetadataHeader` (metadata.go): when the file starts with a `---` fence and a later `---` line closes it (the DOCS_STANDARD ownership header), every byte except \n/\r inside that header becomes a space — "Markdown reads ---, key lines, --- as a heading, which would surface owner names as a section; blanking keeps every offset and line."
- goldmark parse; only headings whose parent is the document (top-level), level <= 4, non-empty trimmed text count. Document title: first level-1 heading text, else filename stem (`name` minus `.md`/`.zh-CN`). Content before the first heading becomes a section titled with the doc title; a heading-less document is one section.
- Sections split at top-level headings; heading trail = `"H1 > H2 > ..."` (clears deeper levels when a shallower one appears). Section id = `"%s::s%03d"` (doc path, 1-based sequence). `searchText` = `title\nheading\nraw`; term counts and length from `retrieval.Tokens(searchText)`; `headingHits` = counts of title+heading tokens; `startLine`/`endLine` 1-based from byte offsets.
- `documentAudience(name)`: stem `THEME_ASSETS | STUDIO_RELEASE | DOCS_STANDARD` → maintainer; `CHECKPOINTS | SPEC | TASK_CONTRACT | TOOL_CONTRACT` → developer; default user. `detectDocumentLanguage`: `*.zh-cn.md` suffix → zh-CN; else content heuristic `han > 100 && han*4 > latin` → zh-CN, else en.

### 6.5 Retrieval helpers (internal/base/retrieval, V1 production path)

- `Tokens(s)`: lowercases Latin words; CJK runs (Han/Hiragana/Katakana/Hangul) split into overlapping bigrams, a lone CJK rune stays a single term — "the standard CJK indexing unit (Lucene's CJKAnalyzer, SQLite FTS)... a bigram only matches a real two-rune subsequence where per-rune unigrams matched scattered common characters." Letters/digits/`_` extend a word; everything else flushes. `Unique` keeps first-seen order. `Counts` = term-frequency map.
- `BM25Score(counts, length, queryTerms, df, totalDocs, avgLen)`: k1=1.2, b=0.75; `idf = ln(1 + (N - df + 0.5)/(df + 0.5))`; classic saturation `idf * tf*(k1+1) / (tf + k1*(1 - b + b*docLen/avgLen))`; zero length/docs → 0. `DocumentFrequency` counts docs containing each term.
- `KeepTopRelativeScore(items, ratio, score)`: callers pass items already sorted best-first; keeps item 0 and every item >= ratio*top; top <= 0 → all kept; "mirrors SQLite FTS/BM25 search UIs that over-fetch, then trim common-word-only noise without imposing an absolute score threshold."
- `QueryTerms(query)`: trimmed → Unique(Tokens) — empty → error `"query must contain at least one letter or number"`.
- `MakeSnippet(text, query, terms, maxRunes)`: `CompactWhitespace` first (fields joined by one space); fits → whole text; else center on the first case-insensitive index of the full query, else the first single-CJK-rune or multi-rune term, else offset 0; window centered `[pos - max/2, pos - max/2 + max)` clamped to rune bounds with `"..."` prefix/suffix when cut.
- Retrieval V2 (v2.go) is SHADOW-ONLY: "BM25F field weighting, code-symbol splitting, and mixed CJK uni+bigrams. Nothing here serves the model — V2 rankings ride the recall audit next to production's, and MemoryBench decides if V2 ever takes over." `TokensV2` (CamelCase/snake_case segment splitting, CJK uni+bigrams, V1 tokens preserved), `v2FieldWeights` (name 2.5, title 2.5, keywords 2.0, subject 2.0, description 1.5, body 1.0 — "candidates under measurement, not tuned truths"), `RankV2` (BM25F, same k1/b), `SortHitsDesc` (score desc, ID asc tiebreak). Production docs tool and /docs use V1 only.


## 7. Builtin support files (confinement, guards, limits)

### 7.1 Workspace confinement (confine.go)

- Confinement constructors override the unconfined instances registered at init: `ConfineBash(spec, guard, timeout...)` (bash bound to an OS `sandbox.Spec`, shell from spec or `sandbox.ResolveShell`), `ConfineWebFetch(proxySpec)` ("preserving its SSRF-guarded dialer"), `ConfineWebImage(roots, guard, proxySpec, receipt)`, `ConfineWriters(roots, guard, managed)` → `{writeFile, editFile, multiEdit, moveFile, notebookEdit, deleteRange, deleteSymbol}`, `ConfineReaders(forbidRoots)` → `{readFile, listDir, globTool, codeIndex}` (grep confined separately so it can carry the sandbox spec for its ripgrep subprocess). Empty roots/forbidRoots = unconfined (the init-time default).
- `BindSessionTemp(tl, *sessiontemp.Manager)` attaches a session-private temp dir manager by type switch: bash, grepTool, writeFile, editFile, multiEdit, moveFile, notebookEdit, deleteRange, deleteSymbol (wrappers that do not unwrap → ok=false). "The composition root adds these to the per-run registry to override the unconfined instances registered at init time, so writes stay inside the workspace by default."
- `realRoots` resolves each root once to absolute, symlink-free paths ("Resolving here (once) means the per-call check only has to resolve the target"); unresolvable roots dropped.
- Read-side deny: `confineRead(forbidRoots, target)` — true when target is inside any forbidRoot, names a credential file (`secrets.CredentialReadPath`), or — with `[secrets] protect_sensitive_files` — matches `sensitiveReadPath` (sensitive base name or under a `secrets.SensitiveHomeDirs()` dir). Unresolvable target → false ("let the caller's normal error path handle it"); callers mimic the directory appearing empty ("matching the tmpfs semantics the bubblewrap sandbox provides"). Deny-side checks fold case on case-insensitive platforms (`withinFold`).
- `CodeReadOutsideScope = "workspace.read_outside_scope"` — `readOutsideScope(scope, target)`: empty scope unconfined; unresolvable target counts as OUTSIDE; refused via typed `tool.Refusal`: "read refused: `<target>` is outside the folders this run may read (<scope>), after following symlinks. This run is read-only and limited to its workspace; nothing else can be read from it".
- `confineOpened(scope, *os.File)` re-checks the actually-opened file ("The check made before opening resolved a name; this one reads the open file, so a link swapped in between cannot carry the read outside"); where the platform cannot report an open file's path the earlier check stands alone (openedpath_{windows,darwin,linux,other}.go).
- `CodeWriteOutsideScope = "workspace.write_outside_scope"` — `confine(roots, target)`: empty roots unconfined; unresolvable → `"resolve %s: %w"`; outside every root → typed Refusal: "write refused: `<target>` is outside the workspace write scope; file tools may write only under <roots>. This scope is enforced by Reasonix's file tools on every platform: it is not an OS sandbox, and it does not depend on whether shell commands are sandboxed. Write inside those directories, or ask the user to add the target's directory to the extra writable directories (Settings > Sandbox > Also writable, stored as allow_write under [sandbox] in reasonix.toml) or to move workspace_root". Paths printed verbatim, never %q ("doubles every Windows backslash and names a file that does not exist as written"). `refuseNetworkPath` checked first (see §7.6 network_scope).
- `confineWrite` order: `confine` (workspace) first; nil or under session temp → `guard.Check(target)`; network refusal passes through; non-managed target → confinement error + session-temp alternative; managed config file → guard check then `managed.approve(ctx, target)` (fresh per-write human approval; without an approver "fails closed with the original confinement error semantics"). Rationale: "a write can be inside the roots (e.g. a home-directory workspace covering the state root) and still be refused when it targets Reasonix's own session stores."
- `withSessionTempAlternative` appends `"; scratch files may also go under $TMPDIR (<dir>)"` to a refusal — "a refused scratch write has somewhere to go that is not the repository." `underSessionTemp`: bash already writes there ($TMPDIR), so refusing it would send scratch back into the repository.
- `confinePreview` mirrors confineWrite for ctx-less diff previews: managed config file passes without approval ("they read the target to render a diff but never write... Execute still gates the actual write").
- `realPath(path)` — resolves as the system would when opening: links and (Windows) junctions followed, re-appending a not-yet-existing tail; "A POSIX path is not cleaned first: a `..` after a link names the target's parent"; nothing exists along the path → `filepath.Clean(abs)`.
- `within(root, path)` via `filepath.Rel` ("correct across volumes and is not fooled by a prefix that only matches a partial path component"); `foldPaths` = windows || darwin; `withinFold` is DENY-side only — "folding an allow rule on a case-sensitive filesystem would wave a genuinely different directory through, whereas folding a deny rule only ever refuses more. On a case-sensitive macOS volume this can refuse a legitimate same-letters-different-case path; the error text points at allow_write / forbid_read config as the way out." ("EvalSymlinks does NOT normalize case, so realPath alone cannot be relied on for this.")

### 7.2 Session-data guard (session_guard.go)

- `SessionDataGuard` rejects agent writes into Reasonix's own session stores (`<state root>/sessions`, `<state root>/projects/<slug>/sessions`) — "the runtime is the only writer of those files (CAS ledger + autosave); an agent editing them from inside a chat races the app's own saves, which surfaces to the user as endless conflict-copy forks." Zero value = unconfined. Built from `config.MemoryUserDir()` + explicit `[sandbox] allow_write` entries (both resolved once, mirroring realRoots): allowRoots "only blocks the accidental self-write path (a workspace root that happens to cover the state root)".
- `Check(target)` tiers (exact texts): (a) security boundary file — `settings.json` directly in the state root (`"path %q is a Reasonix security boundary file (%s holds the global hooks; hooks execute arbitrary shell commands on every future session). Agents may not modify it. Ask the user to edit it themselves, or to add the directory to [sandbox] allow_write in reasonix.toml if raw access is truly intended"`); (b) Trusted Host State → typed Refusal `CodeTrustedStateWrite = "workspace.trusted_state_write"`, `TrustedStateDir = trustedstate.DirectoryName` ("write refused: `%s` is inside Reasonix's trusted host state (%s). The host alone records evidence and contracts there, so agents may not modify it; report the underlying problem instead"); (c) scheduled-runs store → `CodeScheduleStateWrite = "workspace.schedule_state_write"`, `ScheduleStateDir = "schedules"` ("write refused: `%s` is inside the scheduled-runs store (%s). Schedules, budgets and run records are changed by the person through the app, never by an agent, so an unattended run's limits cannot be edited from a chat; report the underlying problem instead"); (d) general session/state data ("path %q is inside Reasonix's own session/state data (%s); the app is the only writer of these files, and edits from a chat race its saves — that surfaces as repeated save-conflict copies. Do not modify session or runtime-state files directly; report the underlying problem instead. If raw access is truly intended, add the directory to [sandbox] allow_write in reasonix.toml").
- `denies` details: `sessions/` tree; state-root-direct runtime ledgers `runtimeStateFile` = names starting `desktop-` ("desktop-tabs.json(+.tmp), desktop-projects.json, desktop-window.json, desktop-workspace...") plus `metrics-pending.json`/`crash-pending.json`; per-project `projects/<slug>/sessions/**` matched positionally. Explicitly NOT denied: `config.toml`, credentials, skills, `heartbeat-tasks.json` ("documented as human- and AI-editable... the product explicitly accepts agent edits racing the engine there"). All deny comparisons case-fold on windows/darwin ("the same shape as the Windows lease-key case split fixed in #6023"); unresolvable target → nil.
- `CommandHint(workDir, command)` — a WARNING appended to bash output (never blocks; "reading session files for diagnostics is legitimate"), one fixed text: "WARNING: this command referenced Reasonix's own session/state data under %s. This is a notice, not a refusal: the command was not blocked, and an empty result above means it matched nothing. To read a spilled tool output (<session>.outputs/), use read_file (offset/limit) or grep rather than shell text tools. The app is actively saving those files; external modifications conflict with its saves and are preserved as conflict copies, so an edit can look like it `did not take`. Do not modify session files from a chat — stop retrying a write and report the underlying problem instead." Lexical lowercase slash-normalized match against precomputed needles (state root as given + symlink-resolved + `~/` and ${HOME`/`/${HOME`/` and `%APPDATA%`/`$env:APPDATA` abbreviations); trees wholly covered by an allow_write root are skipped ("warnings would only nag"); when workDir sits inside the state root, relative forms (../sessions) match too, and a workDir already inside a guarded store warns on every command.


### 7.3 Agent admission check and network-path refusals (target_access.go, network_scope.go)

- `Workspace.TargetAccessCheck()` returns the per-tool path policy bound to `tool.TargetAccessCheck` ("binds one path policy for Agent admission. Existing tool path resolvers also work through path-bound subagent wrappers"). Roots: `w.WriteRoots` (fallback `w.Dir`) + their real forms + `networkSpellings`; read roots/forbidden from `w.ReadRoots`/`w.ForbidReadRoots`.
- Flow: writer tools (`tool.WritesNamedPaths`) resolve targets via `tool.WritePathResolver.WritePaths(args)` (missing resolver → `"cannot resolve file targets for %s"`; `syscall.ENOTDIR` → nil pass-through; zero paths → `"no file targets resolved for %s"`; each path `confinePreview`). Readers via `tool.ReadTargeter.ReadTarget` (then `checkReadNetworkPath`: a host-registered folder ref resolves first and counts as its own root) and `tool.ReadPathResolver.ReadPaths`. Every path then `checkReadTargetAccess`; a `tool.ReadRefusalFormatter` may reformat.
- `checkReadTargetAccess` order: `readOutsideScope` → typed Refusal `CodeReadOutsideScope` with `readOutsideScopeMessage` ("Cannot read `%s`: it is outside the folders this session may read (<roots>). Read a path inside one of them, or ask the user to add the folder." — with empty roots: "...may read. Read a path inside the workspace, or ask the user to add the folder."; "depends only on the policy and the path, never on whether the file exists"); then `confineRead` → `CodeReadForbidden = "workspace.read_forbidden"` with `readForbiddenMessage` ("Cannot read `%s`: it is on this session's forbidden-read list, a protection the user configured, so it cannot be read here." — deliberately does not name the matching entry).
- Overwrite refusals keep the read-policy cause while naming the write action: `CodeOverwriteReadForbidden = "workspace.overwrite_read_forbidden"` (from CodeReadForbidden), `CodeOverwriteReadOutsideScope = "workspace.overwrite_read_outside_scope"` (from CodeReadOutsideScope); both re-message to `overwriteReadAccessDeniedMessage = "Cannot overwrite target file: permission to read existing contents is required."`
- `CodeNetworkPathOutsideScope = fileutil.CodeNetworkPathOutsideScope` — "Windows connects to that machine to resolve the name, so the refusal is made on the spelling, before any lookup." `refuseNetworkPath(target, roots...)` = "the one decision every file tool asks before it resolves a model-supplied path": network path passes only below a root that is itself a network path; local paths always pass; refusal message: "refused: `%s` is a network path, a file on another machine, outside this workspace. It was refused by its spelling and never looked up; file tools reach a network path only below a workspace folder that is itself on the network". `networkRoots` lists CONFIGURED spellings unresolved ("resolving a root that names a share would itself be a lookup"); `networkSpellings` keeps roots already spelled as network paths (Windows only).

### 7.4 Destructive-delete guard (bash_delete.go + interpreter/parser/cmdline)

- Refusal codes: `CodeDestructiveTarget="shell.destructive_target"`, `CodeShellAnalysisUnknown="shell.analysis_unknown"`, `CodeDeleteSequence="shell.delete_sequence"`, `CodeDeleteNonliteral="shell.delete_nonliteral"`, `CodeDeleteOption="shell.delete_option"`, `CodeShellSyntax="shell.syntax_error"`, `CodeParserUnavailable="shell.parser_unavailable"`, `CodeParserTimeout="shell.parser_timeout"`; wrapper prefixes every message with `"Shell command refused before execution: "`.
- `bash.refuseCommand` order: external-reference refusal → `checkCommandLine` → `refuseDestructiveDelete`. Final gate: a command whose analysis saw both a delete and a dynamic payload is refused `CodeShellAnalysisUnknown` "Use a literal interpreter payload or split it from the recursive delete."
- `judgeDelete` (recursive, depth cap 12 → `CodeShellAnalysisUnknown` "Nested interpreter extent is unknown; use a direct delete with a literal workspace path."): analysis via `shellparse.AnalyzeDeleteCalls` (POSIX) or `analyzePowerShellDelete` (PowerShell); parse errors → `CodeShellSyntax` ("Fix the shell syntax and retry: ...") / PowerShell host-parser unavailable → `CodeParserUnavailable` ("The host shell parser is unavailable; retry when the host parser is restored.") / timeout-cancel → `CodeParserTimeout` ("The host shell parser timed out or was canceled; retry the call."). Tracks a working-directory set seeded from `deleteCwd()` (or `sb.WriteRoots`); directory changes (`cd/set-location/sl/pushd/push-location`) extend the set (only literal single-arg paths, cap 64); interpreter calls (`deleteInterpreter`: iex/invoke-expression, powershell/pwsh -Command/-EncodedCommand (base64 UTF-16LE decode), bash/sh -c) recurse into the payload per candidate directory with `unsafe` sticky; recursive deletes must have a literal executable (`CodeShellAnalysisUnknown` "A dynamic executable has recursive-delete arguments..."), no prior unsafe context (`CodeDeleteSequence` "Split the call; only literal directory changes may precede a recursive delete. Assignments and nested control flow cannot establish a safe target."), known options (`CodeDeleteOption` "Use known delete options and common parameters with explicit values."), literal targets (`CodeDeleteNonliteral` "Use a literal target path strictly inside the workspace or granted write roots; expansions, variables, globs and pipeline input are not bounded."), and `boundedDeleteTarget` per directory (else `CodeDestructiveTarget` "Use a target strictly inside the workspace or granted write roots; home, filesystem roots, workspace ancestors and out-of-scope paths are protected in every approval mode.").
- `literalDeletePath`: non-empty, no `$ % * ? [ ] { } ` backtick NUL, and `tildeIsLiteral` (tilde allowed only inside a Windows 8.3 short-name segment `^[^\~/~]+~[0-9]+$` of a drive-letter path — "every other tilde can expand to a home directory"). `boundedDeleteTarget`: literal; Windows root-slash and drive-relative forms rejected; provider-qualified (`:`) rejected; relative joined to cwd; network spelling refused; `realPath` resolution must succeed and not be a filesystem root; not within home (deny-fold); not within the workspace itself ("workspace ancestors" protected — the workspace root can be deleted only by the user); allowed only `within(root, resolved) && !withinFold(resolved, root)` for some write root (session temp dir counts).
- PowerShell delete parser is a persistent `pwsh -NoLogo -NoProfile -NonInteractive -Command` helper running `sandbox.PowerShellUTF8Script(shellparse.PowerShellDeleteServer)` with `secrets.ProcessEnv()`: one JSON request line in, exactly one stdout line out ("diagnostics cannot be mistaken for the next analysis response"), per-shell-path worker with a serializing token; budgets `deleteParserWarmBudget=10s`/`deleteParserColdBudget=90s` ("A call queued behind a cold start waits out that start, so the queue is bounded by the cold budget"); timeout or malformed response kills the worker (next call cold-starts).
- `checkCommandLine` (bash_cmdline*.go): Windows only — counts UTF-16 units of `syscall.EscapeArg`-escaped argv against `windowsCommandLineMax = 32767` ("CreateProcessW's lpCommandLine ceiling in UTF-16 code units, the terminating NUL included"); over → `errCommandLineTooLong` wrapping typed Refusal `CodeCommandLineTooLong = "shell.command_line_too_long"`, message "the command is %d characters and Windows accepts at most %d, so it was not run. Write long text with write_file or edit_file and have the command read that file, or split the work into smaller commands" — "so the model learns the host limit instead of a misleading filename or extension is too long from process creation". Non-Windows: no ceiling. `refusedBeforeLaunch` maps command-line-too-long and external-reference refusals to `ShellPhasePreflight`/`ShellStateNotRun`/`ShellMutationNotStarted`.


### 7.5 File-change tracking, write receipts, setting tool, write-path identity, roots (fileviews.go, post_write_receipt.go, timeout.go, setting.go, write_paths.go, roots.go)

- `FileViews` — "what one run's agent last saw of each file: the content a read returned it from, or what one of its own writes left there. write_file checks it so a whole-file overwrite cannot discard a change made since. A nil *FileViews records and checks nothing." Errors: `ErrFileChangedSinceSeen = "file changed since the agent last saw it"`; `ErrFileNotFullySeen = "...: not read in full"`. `checkOverwrite`: never-seen file not refused; partial-seen → `"%w: write_file replaces all %d lines of %s; read it whole first (read_file with offset 0 and limit >= %d), or use edit_file for a targeted change"`; hash mismatch → `"%w: %s was modified after you last read or wrote it, by the user or another process; read it again and apply your change to what it holds now"`.
- `captureRead` wraps a read renderer: only a complete read (offset 0, EOF reached, within `maxViewBytes = 8<<20`, line count within limit) records content via `saw` (sha256); pages/failed/oversize record `sawPartial` only — "Only a complete returned read can replace an earlier observation. A page, failed read or oversize input must not certify content the caller did not see." `BindFileViews` binds views to readFile, writeFile, editFile, multiEdit, deleteRange, deleteSymbol.
- Post-write replacement receipts (post_write_receipt.go): appended after every edit via `withActualPostWriteReceipts` — summary + `"\nActual replacement receipt after write:\n"` + rendered body. Bounds: `maxPostWriteReceiptBytes = 2048`, `maxCapturedReceiptSpanBytes = 896` ("Mutation receipts are appended to the provider-visible conversation after every edit, so keep their dynamic tail bounded. The receipt contains only the matched and replacement spans, never unchanged same-line or neighboring data."). >2 receipts → first + last only with `"…[%d intermediate replacement receipt(s) omitted]…"`; per-receipt header `"@@ replacement %d of %d (%d occurrence(s)%s) @@\n"` (fuzzy adds ", fuzzy match" and ", first matched sample shown" when occurrences > 1); spans rendered line-by-line with `-`/`+` prefixes, empty → `"<empty>"`; span truncation marker `"…[replacement span truncated]…"`; receipt truncation marker `"…[replacement receipt truncated; use read_file for complete current contents]…"`; `clipUTF8HeadTail` keeps 3/4 head + 1/4 tail around the marker, UTF-8 boundary-safe.
- `toolTimeout(sec int, def, ceiling time.Duration)` (timeout.go): `sec <= 0` → def; ceiling > 0 caps; "bash passes its host cap as both, so a per-call value can only tighten that cap, never raise it."
- Setting tool (setting.go): `SettingTool(link *tool.SettingsLink)` — "A change is only ever applied after the user's own answer to a card the host words; the tool never writes on the model's say-so." `Name "setting"`, `ReadOnly() true` ("the only write waits on the user's own answer to a host-worded card") AND `ReadOnlyExecutionHostMutation() true` ("keeps the tool out of a read-only child, whose parent would otherwise answer for a change it did not read"); `DecisionBarrierCall` true only for `op=propose`. Ops: `list` (host.SettingsList(query) → JSON `{settings, truncated?}` capped `settingListMax = 40`), `propose` (needs id+value else `"setting.invalid_value: op=propose needs an id and a value"`; `host.ProposeSetting(ctx, id, value, reason)` → JSON result), `open` (`"Pointed the user at %s. Only they can change it; carry on without it and say what it blocks."`). No host → typed Refusal `"setting.unavailable"` / "Settings cannot be changed from this session."; unknown op or bad JSON → `"setting needs {\"op\": list|propose|open, ...}"` / `"setting needs op list, propose or open"`.
- Write-path identity (write_paths.go): `canonicalWriterPath(workDir, temp, roots, path)` = `resolveIn(workDir, resolveSessionTemp(temp, path))` → network refusal → `fileutil.CanonicalWritePath` — "the lease and grant identity of a write target. The writers themselves keep the path as the caller spelled it, so receipts, file views and refusals name what the model used." `ResolveWritePaths(...)` parses `path` (or `source_path`+`destination_path` when move) — empty → `"write path is required"`; `ErrAmbiguousPath` tolerated with `realPath` fallback ("returns grant targets even when their narrow lease identity is ambiguous. Lease callers must retain whole-workspace exclusion on error") while other errors fail; implemented by writeFile/editFile/multiEdit/notebookEdit/deleteRange/deleteSymbol (single path) and moveFile (source+destination), webImage (no temp).
- Roots (roots.go) — "each built-in says which directories a call acts under, so the host can find a missing one before the call instead of after a bare system error." `RootsFor(args) []tool.Root` via `pathRoots` (host-registered folder ref → `RootExternal`, else `workspaceRoots`) for readFile/listDir (path defaults "."), globTool (pattern), grepTool (path defaults "."), readVideo; `workspaceRoots` (project folder `RootWorkspace`, suppressed for absolute paths outside it — "that call does not need the folder to exist") for codeIndex, writeFile, editFile, multiEdit; bash: workspace roots + `RootExternal` for every granted token its command names (`b.paths.TokensIn(command)`).


### 7.6 Previews and the edit engine (preview.go, encoding_helpers.go)

- `tool.Previewer` (preview.go): optional capability on the file-writing built-ins — `Preview(ctx, args) (diff.Change, error)` "compute the change a call would make, reading the current file but never writing. A front-end (e.g. a desktop approval card) calls Preview before the permission gate runs Execute." Contract: "Each Preview mirrors its Execute's transformation exactly — same arg parsing, same uniqueness / not-found rules — so the previewed NewText equals what Execute would persist. That equality is asserted by TestPreviewMatchesExecute in preview_test.go, which runs Execute against a temp file and compares; if an Execute body ever drifts, that test fails rather than the preview lying." Three implementors:
  - `writeFile.Preview` — `path` required, resolved via `resolveIn(w.workDir, resolveSessionTemp(w.sessionTemp, path))` + `refuseNetworkPath`; `sourceForWrite` decides `diff.Create` (no prior) vs `diff.Modify`; `diff.Build(path, src.content, p.Content, kind)`.
  - `editFile.Preview` — path + old_string required; resolves `resolveIn(e.workDir, path)` (no session-temp expansion); read error wrapped `"read %s: %w"`; runs `applyOldStringEdit(content, old, new, false)`; applied==1 ok, matches==0 → `oldStringNotFoundError`, else `oldStringNotUniqueError(..., matches, false)` — "a preview never shows a change the call couldn't make."
  - `multiEdit.Preview` — path + non-empty edits; replays every edit against an in-memory buffer exactly as Execute; per-edit errors prefixed `"edit %d: %w"`; `diff.Build(path, original, content, diff.Modify)`.
  - OBSERVATION (upstream asymmetry, §8): writeFile.Preview expands session-temp paths; editFile.Preview and multiEdit.Preview do not pass their sessionTemp — a session-temp target previews (and in editFile's case not-found errors) as a plain workDir-relative path.
- Encoding round-trip (encoding_helpers.go): `readFileEncoded` = `os.ReadFile` + `fileenc.DetectAndDecode` → (content, detected `fileenc.Kind`); `writeFileEncoded` = `fileenc.Encode` + `fileutil.AtomicOverwriteFile(path, data, 0o644)` — atomic because "a truncating write that fails midway (a Windows filter driver holding a transient lock, a full disk) would leave the user's source file empty or half-written." Writers re-encode to the detected kind to preserve the original charset.
- `matchLineEndings`: when the literal `old_string` is absent but its CRLF form is present, search and replacement are rewritten to the file's ending — "read_file strips '\r' (bufio ScanLines), so a model's multi-line old_string arrives LF-only while a Windows/CJK source stores '\r\n'"; fixes the match "without rewriting the file's other line endings." `toCRLF` normalizes `\r\n`→`\n` then `\n`→`\r\n`.
- `replaceLiteral`: swaps exact matches giving each replacement the line ending of the line it lands in — "so a CRLF line never receives a bare LF and an LF line in a mixed file never receives a CR"; returns the first replacement as written (for the receipt). `lineEndingAt` names the terminator of the line holding an offset (that line's own newline, else the previous line's when the file's last line is unterminated; `\r\n` when the newline is preceded by `\r`).
- `applyOldStringEdit(content, oldString, newString, replaceAll) editApplyResult{updated, applied, matches, fuzzy, receipt}` — "the shared edit_file/multi_edit/Preview contract. It preserves the exact-match rule first, then falls back to a narrow fuzzy match for the mismatches read_file introduces or hides: trailing whitespace, tab-vs-spaces indentation, read_file line prefixes, and a blank-line run of a different length. Non-replace_all edits still require exactly one match."
  - replaceAll: exact count>0 → `replaceLiteral` all; else `fuzzyEditRanges` (0 ranges → no-op result with applied=0); ranges → `replaceEditRanges` with `matchReplacementLineEndings`, fuzzy=true.
  - single: exact count 0 → fuzzy; `len(ranges) != 1` → no-op (matches=len(ranges), caller reports not-found); ==1 → fuzzy apply. count 1 → exact `replaceLiteral`. count>1 → no-op with matches=count (caller reports not-unique).
- Fuzzy matching, tried in order: `{trimTrailing}`, `{trimTrailing, expandTabs}` (tab→4 spaces), plus — only when EVERY old line carries a read_file prefix (optional leading blanks + digits + `→` U+2192, `stripReadFileLinePrefix`) — `{stripOldReadPrefixes, trimTrailing}` and `{stripOldReadPrefixes, trimTrailing, expandTabs}`. `fuzzyMode.trimLeading` exists but no mode sets it. Non-overlapping window scan. Invariant in every mode: "an old_string that ends in a newline must not match a final line that lacks one, or the write would append a newline the file never had." `fuzzyWindowEnd` trims the trailing newline (and `\r`) when old lacks a newline and content's last line has one.
- `blankRunRanges` last resort: collapses each run of consecutive blank lines into one token "so only a run's length is free, never its presence: a blank line the caller invented still never matches"; deliberately NOT a `fuzzyMode` "so that it cannot compose with tab expansion or prefix stripping — a span that drifted in two dimensions at once must still fail"; a window that starts or ends blank is rejected ("an all-blank old_string would otherwise name every blank run in the file"); same trailing-newline rule.
- `editReplacementReceipt{matched, replacement, occurrences, fuzzy}` "records only the span the tool actually matched and the span it wrote in its place. It deliberately excludes surrounding file content so a successful edit can ground the next model turn without widening provider-visible workspace data." `matchedRangeSample` clips the first range to `maxCapturedReceiptSpanBytes` and `strings.Clone`s an unclipped sample so a short substring cannot keep a large intermediate multi_edit buffer alive.
- Not-found / not-unique errors (exact texts): `oldStringNotFoundError` — blank-line-presence span (non-blank lines match uniquely but layout differs) → `"old_string not found in %s: lines %d-%d match it only when blank lines are ignored, so its blank lines differ from the file's there. Copy that span again with every blank line exactly as the file has it."`; nearest content line (normalized common-prefix score >= 3) → `"old_string not found in %s (nearest line %d: %q).%s"`; else `"old_string not found in %s.%s"`. Hint: base `" Re-read the current file before retrying; if several related edits target the same area, combine the final replacements in one multi_edit call."`; CRLF file + LF-normalized hit → `" The target file uses CRLF line endings; edit_file/multi_edit normally normalize LF-only old_string for CRLF files, so this is likely stale context. Re-read the current file before retrying."`; CRLF file, no normalized hit → `" The target file uses CRLF line endings, but edit_file/multi_edit already tolerate LF-only old_string for CRLF files; check for stale, incomplete, or non-unique context before retrying."`. `oldStringNotUniqueError` → `"old_string is not unique in %s (%d matches)%s; add nearby unique code, not just repeated separator lines"` (+ `", or set replace_all if every match should change"` in the multi_edit form), line hint `"; matching lines include 1, 4, ..."` capped at 5 matches via `oldStringMatchLineSummary` (first non-empty old line contained in content lines).


### 7.7 Workspace binding, path resolver, walk pruning (workspace.go, fileviews_binding.go)

- `Workspace` (workspace.go) "builds a built-in tool set bound to a working directory, so several agents can run concurrently with independent path roots — a desktop front-end opening one tab per project, say. The process working directory is global and cannot be made per-agent (os.Chdir is process-wide), so each tool instead resolves relative paths against this directory and bash runs in it." Fields: `Dir` (empty = process-cwd tools, byte-identical to compile-time built-ins); `WriteRoots` (ConfineWriters; when empty and Dir set, Dir becomes the sole write root, "so writes stay inside the project by default"); `ForbidReadRoots` (read/list/search cannot peek); `ReadRoots` ("when set, confines every read tool to these directories after symlinks are resolved; empty leaves reads unconfined"); `Bash sandbox.Spec` / `BashTimeout` / `Search SearchSpec` / `ProxySpec` / `SystemOne SystemOneSpec`; `ReadPaths *PathResolver`; `SessionGuard SessionDataGuard`; `ManagedConfig ManagedConfigPaths` ("names the Reasonix-owned config files the file-writers may touch outside WriteRoots after a fresh per-write human approval ... The zero value disables the escape hatch"); `FileOverlay` + `Terminal` ("when non-nil, serves every file tool's content through the host transport (unsaved editor buffers) with disk fallback"/"runs foreground bash in a host-owned terminal when the local OS sandbox is not enforcing. Both are nil outside host transports like ACP"); `SessionTemp *sessiontemp.Manager` ("shared by bash and ripgrep-backed grep. Nil leaves those tools without a session-private temp (platform defaults apply)"); `FileWriteReceipt func(path string, hadPrior bool, prior []byte)` ("receives prior-state evidence after a successful write_file mutation. It is instance-scoped so concurrent runtimes never record into another session's recovery ledger").
- `Workspace.Tools(enabled ...string)`: empty enabled list yields every built-in; otherwise only the named ones ("unknown names are ignored"). Computes `roots = realRoots(writeRoots) + networkSpellings`, `netRoots`, `forbidRoots`, `readRoots`; INVARIANT: "A scope that resolves to nothing must refuse everything, not confine nothing" — ReadRoots set but `realRoots` resolves none → `readRoots = [filepath.Join(string(filepath.Separator), "\x00unresolved")]` (unresolvable sentinel). 16 bound overrides by name: read_file, write_file, edit_file, multi_edit, move_file, notebook_edit, delete_range, delete_symbol, code_index, bash, ls, glob, grep, read_video, web_fetch, import_web_image — each re-instantiated with the workspace's fields; `tool.Builtins()` entries replaced in place by Name(). `SystemOne` appended when `SystemOneConfigured` (always in the empty-enabled form; in the filtered form only when "system_one" is in the enabled list).
- `resolveIn(workDir, p)`: empty workDir → p unchanged ("the process-cwd behavior the compile-time built-ins have always had"); `p == "" || p == "."` → workDir ("a defaulted '.' (ls/grep) targets the workspace root"); absolute p → returned as-is ("an explicit absolute path is honored verbatim — the write-confiner, not this, enforces the workspace boundary"); else Join(workDir, p).
- `resolveSessionTemp(temp, p)`: "rewrites a leading session-temp variable into the directory it names. The host exports these spellings to bash and names $TMPDIR in its own refusal text, so a writer that cannot read them creates a literal `\$TMPDIR` directory inside the workspace. Only the first segment is expanded." First path segment matched against `sandbox.SessionTempEnvKeys` as `$KEY`, `${KEY}` or case-insensitive `%KEY%`; on match, lazily `temp.Acquire()`s a lease when the generation does not yet exist ("usually bash" creates it first) then `Release`es; joins the temp dir with the remainder.
- `PathResolver`: "maps session-authorized token paths to local read-only roots. It is intentionally used only by read tools; write tools continue to rely on WriteRoots confinement and never resolve these aliases." `sync.RWMutex` + roots map, created by `NewPathResolver` (root set updatable after the workspace tools are registered). `RegisterReadRoot(token, root)`: token via `normalizeReadToken` (TrimSpace, strip leading `@`, ToSlash, TrimRight `/`), root via `filepath.Clean(TrimSpace)`; empty either side ignored. `Resolve(path) (ResolvedPath, bool)`: exact token → root; `token/` prefix → `cleanReadSubpath` (must be `filepath.IsLocal`, no traversal) joined under root; `ok=false` for ordinary workspace paths. `TokensIn(command) []string` names the registered tokens a command mentions — "The registry is the authority: these keys were minted by the host, so finding one is recognition rather than a guess about what a word might mean" — sorted.
- `ResolvedPath{Path, DisplayPath, Root, DisplayRoot, External}` "carries both the local path used for I/O and the token path that should appear in tool output": `DisplayFor(path)` rewrites local paths under Root back to the token spelling (raw path fallback when Rel fails or escapes); `ErrorText(err)` `ReplaceAll(msg, Root, DisplayRoot)` — external error text never leaks the local root. `resolveReadablePath`: resolver first, else `resolveIn` wrapped as a non-external ResolvedPath.
- Walk pruning: `vendorDirs` = .git .svn .hg .jj node_modules vendor .venv `__pycache__` .mypy_cache .pytest_cache — "dependency, VCS, and build-cache trees that almost never hold the searched source and would otherwise dominate the walk (node_modules alone can be 100k+ files) and fill the result cap with noise. Only skipped when nested — a walk rooted directly at one (an explicit `grep node_modules`) still searches it." `skipWalkDir` never prunes the walk root itself and also prunes `isProtectedDir(absClean(path))`; `skipForbidDir` = `confineRead(forbidRoots, path)`.
- `ForkFileViews(reg *tool.Registry) func(tool.Tool) tool.Tool` (fileviews_binding.go): "gives direct and deferred file tools one new actor-owned record" — creates one `FileViews`, returns a bind func that wraps any tool carrying views (readFile, writeFile, editFile, multiEdit, deleteRange, deleteSymbol — NOT moveFile or notebookEdit) and re-`Add`s already-registered tools in place, so tools registered later get the same record.


## 8. Divergences (docs vs source) and open decisions

1. **Guidance prompts name an unregistered tool.** `/plan-exec` (`session/control/turn_submit.go:535-536`: "Research/exploration across modules = use parallel_tasks", "Dispatch each batch via parallel_tasks — each sub-agent gets one module's context") and `/prometheus` (`session/control/controller.go:697`: "For independent research directions, use parallel_tasks before planning") instruct the model to use `parallel_tasks`, which is **not a registered tool** (§3.9). The guidance text is observable behavior, so the default is text parity per AGENTS.md §3.1 — reproduce these strings byte-for-byte in Rust; a provider that follows them fails through the same unknown-tool path as in the reference. Recorded in `docs/parity/BREAKS.md`.
2. **Preview session-temp asymmetry (upstream inconsistency, match it).** `writeFile.Preview` expands session-temp spellings (`resolveSessionTemp`) but `editFile.Preview` and `multiEdit.Preview` resolve only against `workDir` (§7.6). Parity requires reproducing the asymmetry: an edit_file/multi_edit preview of a session-temp target behaves differently from its Execute.
3. **`turn_exit_tools.go` comment drift.** The comment describes three ways a turn ends but only two tools are registered (`ask`, `await_user`). Comment-only drift, non-blocking; the registration set in §3.7 is authoritative.
4. **Retrieval V2 is shadow-only.** `internal/base/retrieval/v2.go` (BM25F, TokensV2, v2FieldWeights) has no production caller; the docs tool's ranking is V1 (§6.5). Rust port: implement V1 exactly; do not port V2 unless a production caller appears — it is not observable behavior.
5. **Catalog table completeness.** §2.1 lists 33 registrations; `view_image` is a 34th workspace tool surfaced through workspace assembly and is documented in §3.7 — the Rust catalog must include it.
6. **Embedded docs corpus parity (engineering constraint).** The corpus is `go:embed` of the repo-root `docs/*.md` tree (104 files, §6.3). The Rust build must embed the same file set with byte-identical contents or the sha256 manifest digest diverges; `buildIdentity`'s release-stamped version/revision (and `vcs.revision`/`+dirty` fallbacks) needs an equivalent Rust build-script mechanism so `docs read` identity output matches release formats.
7. **`bash_output` prose promises task support.** `internal/tools/jobs` surfaces a task job's result once in `Output` ("bash_output promises task support", §5.1) although `task` is not registered (§3.9). Keep the prose and the code path (a task-kind job can exist for legacy/compat reasons); do not register `task`.
