## 0. Overview

- The Extension Protocol is the stable wire contract between Reasonix (host) and code extensions running as out-of-process sidecars: an installed plugin with a `runtime` block intercepts runtime events, owns replacement strategies, contributes streaming model providers, and publishes structured UI — without ever linking into the host binary.
- Protocol ID `reasonix.extension.v2`, protocol major 2. Machine-readable schema: internal/ext/extension/protocol/schema.generated.json; schema hash sha256:a0716fcfa8aab0f67a5c2299c4e6fa1573378e44c6050633a930d6d736f35fd7 (generated by cmd/extension-protocol-gen; CI's deterministic-generation test enforces committed drift). Where prose and generated index disagree, the generated schema wins.
- Plugin manifest compatibility: exact `apiVersion: reasonix.io/plugin/v2` only — no v2.0/v2.1 aliases; v1 and legacy native manifests are REJECTED with no dual-read and no automatic migration (v2 is the first publicly supported runtime manifest).
- Handshake `provides` must be a subset of the manifest provides ceiling.

## 1. Transport (docs/EXTENSION_PROTOCOL.md)

- Strict JSON-RPC 2.0 over NDJSON: one complete JSON object per line on stdin/stdout. stderr belongs to the extension for diagnostics; the host captures a bounded, credential-redacted tail for errors.
- Frames capped at 8 MiB (frameBytes 8388608) in BOTH directions; oversized frames are connection-fatal `frame_too_large`.
- Request IDs are integers. params must be an object. Unknown members are tolerated at the FRAME level; DTO decoding is STRICT (unknown fields rejected) so typos surface immediately.

## 2. Lifecycle

1. Host spawns the sidecar (exec form, no shell) and sends `extension/initialize` first; params carry the manifest expectation — the intercepts, replaces, providers, and UI actions the host will accept. For one runtime generation the host initializes at most FOUR sidecars in parallel under one shared 30-second startup budget.
2. Sidecar answers with its declaration; host validates: exact protocol major version, and every subscription, replacement slot, provider, and UI action must be a SUBSET of the plugin manifest — anything beyond the manifest fails the handshake with `capability_not_declared`.
3. Host sends `extension/initialized`. Any extension-to-host traffic before this point poisons the connection.
4. Shutdown is bounded: `extension/shutdown` with a timeout, then stdin closes, then the process tree is killed if the sidecar does not exit.
5. Crashes: a dead sidecar cancels all its pending RPCs; if it owned the currently selected provider or a replacement slot, the current operation FAILS EXPLICITLY — the host never silently falls back to another model or strategy. A crashed sidecar is only restarted by an idle-time runtime reload.

## 3. Content references

- Payload fields marked externalizable that exceed 64 KiB (externalizeFieldBytes 65536) are offloaded into the host content store: the frame carries an ExternalizedField descriptor (JSON pointer, content ref, byte count, SHA-256) and a null placeholder.
- The peer pages bytes back with `host/content/read` in 256 KiB chunks (contentRefChunkBytes 262144), verifying byte count and hash. A single content object is capped at 8 MiB (contentRefObjectBytes 8388608). Unknown/expired refs fail with `content_ref_expired` (retryable).

## 4. Interception

- Seventeen frozen hook points shared by `extension/intercept` (blocking) and `extension/event` (fire-and-forget observation of the same points): agent.before_start, compaction.complete, compaction.prepare, context.prepare, frontend.event, input.receive, permission.decision, provider.request, provider.response, session.end, session.load, session.rotate, session.save, session.start, system_prompt.build, tool.after, tool.before.
- Event delivery uses a bounded non-blocking writer queue: saturation DROPS the observation with a warning instead of stalling the Agent.
- Ordinary interceptors run SEQUENTIALLY in deterministic order: priority ascending (manifest priority, -1000..1000, default 0), then plugin ID, then registration order.
- Decisions per call: `continue` (pass payload along), `block` (abort with a user-visible reason), `replace` (substitute the payload — host re-validates it against the point's DTO and schema before use), and `allow`/`deny` (only legal at permission.decision). A full-trust `allow` overrides a host deny and is audited.
- A `block` at tool.before may carry an `answer`: the tool does not run and the text stands in for its output, labelled by the host as external data from the extension. An answer anywhere else is a contract violation.
- At input.receive a replacement may add `context` blocks (label, text): they follow the input on the turn's tail under a host-written header naming the plugin that added them, bounded by the user's ceilings; a later extension may add blocks but not change an earlier one's.
- Replacement strategy slots — system_prompt, context, provider_request, provider_response, compaction, session_policy, permission, frontend_events, tool:<name>, provider:<ref> — have EXACTLY ONE owner across all installed plugins. The chain runs first; the slot owner gets the final say. A strategy owner's timeout or error always fails the operation.
- Timeouts: input/tool/permission points default to 5s; the session/context/compaction/system-prompt family to 30s; a manifest may tune per-runtime up to a 60s ceiling. Optional observation-only extensions that time out are warned about once and skipped; required extensions and slot owners fail the operation (`intercept_timeout`, retryable).

## 5. Streaming providers

- An extension with the `providers` capability answers `extension/provider/catalog` with descriptors equivalent to host providers (models, context windows, pricing, vision, reasoning, effort) — NEVER credentials. Models appear as `plugin/<plugin>/<provider>/<model>`.
- Streams follow `extension/provider/stream/open` → `stream/chunk` → `stream/end`: chunks carry a 1-based contiguous sequence number; `stream/end.lastSeq` freezes the terminal boundary. The host buffers out-of-order chunks, drops duplicates, and fails the stream as interrupted naming the missing sequence when a gap persists (`stream_gap`).
- Chunk types: text, reasoning (with signature), tool_call_start, tool_call_args_delta, tool_call, usage (including cache tokens), done, error. Provider errors must be redacted by the producer and are defensively redacted again by the host.
- Cancelling the stream context sends `stream/cancel`; the sidecar must stop producing chunks (`stream_cancelled`).
- The extension reads its own environment and credentials; the host never sends another provider's API keys or headers. A crashed provider never triggers fallback to a different model.

## 6. Structured UI

- Extensions with the `session.read` capability read the session (`host/session/read`: `usage` or `messages`, redacted and bounded by the user's ceilings); those with `session.submit` queue a prompt (`host/prompt/submit`); neither implies the other.
- A queued prompt is the host's message about the extension, labelled with its source — never the user's words; the host may refuse it with a `refused` identity in the result (`submit_per_turn`, `submit_bytes`, `no_session`).
- Extensions with the `ui` capability publish `status`, `card`, `form`, `notification`, `panel`, and `view` payloads (`host/ui/publish`) and ask questions (`host/ui/request`: confirm, input, select, multiselect).
- Surfaces are structured ONLY: no HTML, CSS, JavaScript, remote scripts, arbitrary frontend components, or uncontrolled URLs; Markdown renders through each frontend's existing safe renderer.
- Every surface update carries the plugin ID, surface ID, session ID, and runtime generation; stale-generation updates are dropped so late results after a tab switch or reload can never overwrite current state.
- A `panel` holds a place in the frontend's side rail rather than scrolling past in the transcript: re-publishing the same surface id updates what is already on screen. A `view` is composed rather than filled in: its payload is a tree of host primitives, for a shape the fixed kinds do not have.
- Actions declared at initialize are namespaced `/<plugin>:<action>` and are invoked via `extension/ui/action`; form submissions arrive via `extension/ui/submit`.

## 7. Tools

- Declared in the manifest: each tool's name, description, and input schema sit under `runtime.tools`, so the host knows them before the process starts and an install plan shows them.
- Activated at initialize: `InitializeResult.tools` names the declared tools this process serves; a name the manifest does not declare fails the handshake with `capability_not_declared`. `ManifestExpectation.tools` tells the extension which names the host will accept.
- Called through the host: the model sees each tool as `ext__<plugin>__<tool>` and reaches it through the capability catalog, as it does MCP tools, so installing a plugin never moves the cached prompt prefix. Every call passes the host's permission check first.
- Answered by `extension/tool/call`: params carry the declared `name`, the model's `arguments`, and a `timeoutMillis` budget (5 minutes today).
- Two kinds of failure: the result's `content` is what the model reads, and `isError` marks a failure the tool reports about its own work. A call the extension cannot run at all answers with a protocol error instead.

## 9. Stability contract

- Within major version 2, the only permitted evolutions are: new optional fields, new enum values, and new methods. Existing required fields, directions, limits, error reasons, and semantics never change.
- The canonical schema and its SHA-256 hash are produced by cmd/extension-protocol-gen; CI's go test enforces this via the deterministic-generation test (TestGeneratedArtifactsAreDeterministicAndCommitted), so any drift — including an accidental semantic change — fails the build.

## 10. Security model

- A code extension is FULL TRUST: it runs outside the Reasonix sandbox with the unfiltered inherited environment, can read the full session and environment, can bypass permissions, and can operate the machine directly.
- Installing, updating, replacing, or --linking a plugin with a runtime block IS the authorization — there is no second confirmation. Only plugins installed through the plugin flow (recorded in plugin-packages.json) can start a sidecar; project configuration can never declare one.
- Before any sidecar diagnostics, structured UI, interceptor reasons, or provider errors reach the UI, logs, or error surfaces, the host runs its credential redaction pass. Ordinary provider/model content is preserved as product data.
- The install preview, plugin details, and capability diagnostics always display the FULL TRUST block for runtime plugins.

## 11. Runtime v2 model (docs/EXTENSION_RUNTIME_V2.md, "Spatiotemporal Composability")

- Core types: RuntimeSnapshot = immutable config + dependency view; RuntimeSet / EffectScope = live resources for one generation; RuntimePlan = old → new transition (subgraph classification); RuntimeOwner = one session lineage's gate + receipts + stream/file evidence; Controller = published generation consumer (admission bound to RuntimeOwner).
- Component states: Inactive → Preparing → Active → Draining → Inactive (or Failed).
- Rebuild: prefer boot.RebuildFrom(previousBuildResult, opts). No-op / interceptor / UI / provider / MCP-only plans use a TRUE subgraph patch (no BuildRuntime) and set ReusedController so callers must not Close the old pointer.
- Provider/MCP subgraph: live sidecar contributions refresh interceptor/provider/UI catalog via WithLiveContributions; system prompt + tool schemas + CacheHash stay stable (backend roll only). Tool schema renames still require full rebuild.
- Narrow path is stage → ready → commit (fail-atomic): stage starts/adopts sidecars and builds the next dispatcher/resolver but does NOT install stream routers or BindGeneration on the UI hub; ready awaits sidecar readiness; commit installs stream routers, binds UI generation, replaces controller bindings, then publishes. On any stage/ready/commit failure, RollbackPlanStart reattaches Unchanged clients; pre-stage stream routers keep consuming stream/chunk / stream/end.
- UI during stage: the previous UI hub generation stays bound until commit. Sidecars that emit host/ui/publish or host/ui/request with the staged (next) generation during handshake/ready are DROPPED as stale. Protocol policy: do not rely on UI visibility before the runtime generation is published.
- After successful migration: publish new generation, then drain old sidecars. Drain timeout cancels registered work (controller when replaced, host provider streams via HostStreamRegistry, extension provider streams, StableProxy/MCP in-flight) then writes drain-timeout receipts. Draining controllers reject new turns (turnDroppedDraining).
- Diagnostics: reasonix doctor runtime [--json], reasonix plugin doctor <name> — component status, plan, effect receipts, recoverability, lifecycle metrics, and the process-local runtimeOwnerFallbacks count (product boot binds an isolated owner; non-zero fallback identifies compat code reaching the shared default owner). With no live runtime to ask (CLI case), recoverability and resume are reported unknown (JSON null): effect receipts live only in the process that owned the runtime.
- Plan diagnostics separate two facts: prefixChanged is computed after build by comparing the previous and current snapshot CacheHash; providerChanged reports provider capability additions, removals, or reloads. A provider-only backend roll reports prefixChanged=false, providerChanged=true when the provider-visible system prompt and tool schemas remain byte-identical.
- Effect receipts: irreversible external work is recorded in the current RuntimeOwner's receipt store; independent sessions never share publish/drain state or recovery evidence; recovery never claims successful rollback for irreversible effects; owner-scoped AssessRecoverability(generation) / DecideResume(generation). The receipt ledger supports in-process rebuild/resume ONLY (not persisted — recovery after a process crash is outside runtime-v2 scope). Memory bounded to the latest 32 generations and 256 receipts per generation; eviction also drops associated file-prior bytes and marks the affected generation's evidence truncated, so diagnostics refuse to claim a clean rollback when complete evidence is no longer available. Message-send dedup follows the same retention: evicting a message receipt releases its (generation, messageID) key instead of growing a second unbounded ledger. File priors capped at 8 MiB per entry and 32 MiB per RuntimeOwner; writes beyond either limit record prior_truncated and recovery remains conservative. Provider stream open records provider-submit:<id> (irreversible). Completed provider streams unregister their drain callback; only in-flight streams remain retained by the generation gate. Drain timeout force-expire records drain-timeout:<gen>; ScheduleDrainWatch starts only when a generation is actually draining and coalesces rapid publishes into one watcher per owner; the doctor sweep remains a fallback. Late-cancel expiry markers retain the latest 256 generations per owner.
- EffectScope ownership table (live resources for one generation tracked on RuntimeSet / EffectScope): sidecar manager = Cancelable effect in activator; UI hub binding = TrackUIHub; MCP plugin host = Inventory + session-resources dispose; LSP manager = TrackWatcher inventory; session cleanup chain = TrackControllerCleanup; provider submit = RecordProviderSubmit receipt.
- Phase 5 decisions: v2 is the first supported extension runtime manifest (install/doctor/boot do not dual-read v1, do not auto-migrate); performance notes in docs/EXTENSION_RUNTIME_V2_PERF.md; v2 manifest examples under sdk/go/examples/*; protocol gen remains the source of truth for wire types.

## 12. protocol/ package — frozen wire contract (internal/ext/extension/protocol/)

### 12.1 Identity and limits (protocol.go, limits.go)

- `ProtocolID = "reasonix.extension.v2"` (also the generated schema document's $id); `ProtocolMajor = 2`; `ProtocolVersion = "2"`.
- `CompareProtocolVersion(peerID, peerVersion)`: peer ID must match ProtocolID exactly (else `unsupported_version`); version must parse as an integer (else `protocol_error`) and its major must equal 2 (else `unsupported_version`).
- Frozen limit constants (frozen into the generated schema; changing one changes the schema hash): FrameBytes = 8<<20 (8388608), ExternalizeFieldBytes = 64<<10 (65536), ContentRefChunkBytes = 256<<10 (262144), ContentRefObjectBytes = 8<<20 (8388608).
- `ValidateFrameSize(bytes)` rejects bytes <0 or >FrameBytes with the frozen frame_too_large ProtocolError. `RequiresExternalization(payloadBytes)` = payloadBytes > ExternalizeFieldBytes.

### 12.2 Enums (enums.go)

- Direction: host_to_extension_request, extension_to_host_request, host_to_extension_notification, extension_to_host_notification; `IsNotification()` for the two notification directions.
- OperationClass: lifecycle, intercept, observation, provider, ui, content, tool, session.
- InterceptEvent: the 17 frozen hook points (§4); `InterceptEvents()` returns them sorted; count pinned by tests and frozen into the schema.
- InterceptDecision: continue, block, replace, allow, deny, AND `ask` — legal only at permission.decision and only for a runtime that may merely tighten: it puts the call to the user even where the host allowed it (NOTE: `ask` appears in enums.go but not in the prose docs — six decisions, not five).
- UIHostKind: tui, desktop, acp, headless. UISurfaceKind: status, card, form, notification, panel, view. UIRequestKind/UIFieldKind: confirm, input, select, multiselect (form fields deliberately mirror request kinds). UISeverity: info, warn, error.
- ProviderRole: system, user, assistant, tool. ProviderChunkType: text, reasoning, tool_call_start, tool_call_args_delta, tool_call, usage, done, error. ProviderErrorCode: provider_failed, provider_interrupted (raw provider errors NEVER cross the wire — only these codes and generic messages do).
- ContentEncoding: utf8 (only value).

### 12.3 Errors (errors.go)

- `DomainErrorCode = -32000`; errors mapping onto standard JSON-RPC failures use standard codes instead: protocol_error→rpcwire.ErrInvalidRequest, unknown_method→ErrMethodNotFound, invalid_params→ErrInvalidParams, internal→ErrInternal (all from rpcwire).
- `frozenErrorSpecs` table: 20 reasons, each {Code, Message, Retryable} exactly as §8 (messages verbatim, e.g. protocol_error → "The extension protocol frame or envelope is invalid.").
- `ProtocolErrorData{Reason, Retryable}` is the structured JSON-RPC error data; `Validate()` rejects unknown reasons and retryable values that disagree with the frozen table.
- `ProtocolError{Reason, Message}`.RPCError() builds the transport error with the frozen code + structured data; `NewProtocolError/MustProtocolError` build frozen errors; `ErrorContracts()` returns the table sorted by reason (schema/documentation-visible form, JSON keys reason/jsonRpcCode/message/retryable).

### 12.7 Content DTOs (dto_content.go)

### 12.8 Provider DTOs (dto_provider.go)

- `ProviderDescriptor{ref, displayName?, model?, contextWindow?, pricingCurrency?, cacheHitPerMillion?, inputPerMillion?, outputPerMillion?, vision?, tools?, reasoning?, efforts?, defaultEffort?, toolCallReasoning?, reasoningRoundTrip?}` — mirrors provider.Descriptor; never endpoints/credentials/headers/env names.
- `PluginRefOwner(ref)`: extracts plugin ID from `plugin/<pluginID>/<rest...>`; the two-segment `plugin/<model>` shape stays an ordinary host ref and returns "".
- `ProviderMessage` keeps provider.Message's snake_case JSON names (role, content, images, reasoning_content, reasoning_signature, tool_calls, tool_call_id, name) minus local-only UI metadata; content is externalizable. `ProviderToolCall{id, name, arguments, thought_signature?}`; `ProviderToolSchema{name, description?, parameters RawMessage}`; `ProviderResponseFormat{type}` (optional).
- `ProviderRequest{messages, tools, temperature?, maxTokens, responseFormat?}` — nil Messages/Tools arrays are INVALID (empty arrays canonical); every tool's parameters must be a valid JSON object; maxTokens ≥ 0.
- `ProviderUsage{promptTokens, completionTokens, totalTokens, cacheHitTokens, cacheMissTokens, reasoningTokens, finishReason?}`; `ProviderError{code, message}` (deliberately generic).
- `ProviderChunk{type, text?, signature?, toolCall?, argChars?, usage?, error?, generation?, epoch?}` — Validate: argChars ≥ 0; error chunks require error; non-error chunks forbid error; usage chunks require usage.
- `StreamOpenParams{streamId, providerRef, model?, effort?, request, seqBase, generation?, epoch?}` (seqBase ≥ 0; chunks numbered from SeqBase) → `StreamOpenResult{accepted}`; `StreamCancelParams{streamId}` → `StreamCancelResult{cancelled}`; `StreamChunkParams{streamId, seq ≥ 1, chunk, generation?, epoch?}`; `StreamEndParams{streamId, lastSeq ≥ 0, error?, interrupted?}` — lastSeq freezes the terminal ordering boundary; receiver must hold chunks 1..lastSeq or it is a stream_gap; interrupted=true means cut mid-flight (transport drop or cancel) vs clean finish/fail.

### 12.9 Session DTOs (dto_session.go)

- `SessionReadParams{what: usage|messages, limit? (0 = host default)}` → `SessionReadResult{usage? SessionUsage, messages? []SessionMessage, omitted?}`; `SessionUsage{promptTokens, completionTokens, cachedTokens}`; `SessionMessage{role, text}` (credential-redacted, bounded).
- `PromptSubmitParams{text}` → `PromptSubmitResult{queued, refused?}`; refusal identities: `submit_per_turn` (per-turn ceiling spent), `submit_bytes` (over byte ceiling), `no_session` (no saved path yet) — a host-chosen refusal is NOT a protocol error.

### 12.10 Tool DTOs (dto_tool.go)

- `ToolCallParams{name (manifest-declared name, NOT the host-qualified ext__ name), arguments RawMessage, timeoutMillis}` → `ToolCallResult{content, isError?}`.

### 12.11 UI DTOs (dto_ui.go, dto_view.go)

- `UIActionDecl{actionId, label?}`; `UIActionParams{actionId, sessionId, generation, args? map[string]string}` → `UIActionResult{accepted, message?}`; `UISubmitParams{surfaceId, sessionId, generation, values map[string]any}` → `UISubmitResult{accepted}`.
- `UIPublishParams{surfaceId, sessionId, generation, kind, payload RawMessage}` → `UIPublishResult{accepted}`; `UIRequestParams{surfaceId, sessionId, generation, kind, payload}` → `UIRequestResult{cancelled, values?}` (cancelled distinguishes dismissal from empty values).
- Payload types: `UIStatusPayload{label, detail?, severity?, progress?}`; `UICardPayload{title?, markdown?, text?, fields? []UIKeyValue, progress?, actions? []UIActionRef}`; `UIPanelPayload` (card shape MINUS markdown — the side rail is a narrow column; a long story publishes a card into the transcript); `UIFormPayload{title?, message?, fields []UIFormField{key, label?, kind, options?, default?, required?}}`; `UINotificationPayload{title, body?, severity?}`.
- `DecodeUIPublishPayload` strict-decodes the kind's payload (unknown kinds, unknown fields rejected); `DecodeUIRequestPayload`: EVERY request kind carries a UIFormPayload-shaped document (a confirm is a form with one confirm field or a bare message).
- View tree (dto_view.go): `UINodeKind` = text, markdown, row, stack, kv, meter, pip, button, divider (9 primitives; deliberately small — nothing describes size/position/colour). `UITone` = dim, strong, ok, warn, err, accent (what a node means, not what colour it is — the host owns the palette).
- Node tree limits (part of the contract, not a host's private defence): MaxViewNodes 200, MaxViewDepth 8, MaxViewText 4000, MaxViewLabel 200, MaxViewSlotID 64; MaxAnchorLen 128.
- `UINode{kind, value?, key?, label?, tone?, progress?, actionId?, children?}` — flat shape (not a union) so every consumer handles it identically; which fields a kind may carry is enforced in Validate, not by the type.
- `UIViewPayload{slot?, anchor?, body []UINode}`: slot is a name, not a position — an unrecognised one degrades to the host's default place; `AnchorTool = "tool:"` prefix — anchor "tool:<callId>" replaces the card body of a tool call; ONLY tool calls are addressable (closed list is the safety property: nothing else in the transcript can be redrawn; the host keeps every card's frame and attribution). A view cannot both stand in a slot and replace a card. Validate: slot ≤ 64, anchor ≤ 128 with tool: prefix and non-empty callId, body non-empty, node budget/depth/length checks, per-kind field rules (text/markdown need value; kv needs key; pip needs tone; button needs actionId AND label; meter needs progress 0..1; row/stack need children; leaves cannot have children).

### 12.12 Strict decoder and schema generation (validate.go, schema.go, schema_hash.generated.go)

- `enumTypes` freezes the allowed wire values of every string enum (16 type keys incl. ErrorReason); `EnumValues()` is the exported form for code generators — the strict decoder, JSON Schema, and SDK DTO mirror all draw from this one table.
- `decodeAndValidate` is the single strict decoder: required-field presence (json tag analysis: non-omitempty fields must be present; `nullable:"true"` or `externalizable:"true"` fields may be null, others may not), `DisallowUnknownFields`, trailing-JSON rejection, tag validation (nonempty, min=, max=, sha256 = ^[0-9a-f]{64}$), nested required validation through slices, and semantic `Validate()` methods.
- Error messages: "params.%s is required", "params.%s must not be null", "%s has invalid enum value %q", "params must be a JSON object", "params contain trailing JSON", "params do not match the registered type".
- `ExternalizablePointers(typ)` lists schema-level JSON pointer patterns ('*' for array items) of fields tagged externalizable, via RFC 6901 token escaping (~→~0, /→~1).
- `BuildSchemaDocument()` reflection-walks the frozen registry into the canonical JSON Schema draft 2020-12 document ($schema, $id=ProtocolID, title "Reasonix Extension Protocol v2", protocol/protocolID/protocolMajor, limits object, interceptEvents, errors, methods {direction, class, params, result, notification}, $defs). Named structs become $defs entries (closed objects: additionalProperties:false, required from omitempty analysis, tag-derived minLength/minimum/maximum, x-externalizable annotation); json.RawMessage/any become the boolean schema true; map[string]any becomes object with additionalProperties. `CanonicalSchemaBytes()` = deterministic compact JSON (encoding/json sorts map keys). `SchemaHash()` returns the committed `GeneratedSchemaHash = "sha256:a0716fcf...f35fd7"` (schema_hash.generated.go, DO NOT EDIT; tests independently recompute from CanonicalSchemaBytes to reject stale generated artifacts).

## 13. rpcwire/ — transport-neutral JSON-RPC 2.0 over NDJSON (internal/ext/extension/rpcwire/)

Contains NO extension lifecycle or capability semantics — the wire only.

### 13.1 Error codes and error types (errors.go)

- Standard JSON-RPC 2.0 codes: ErrParse -32700, ErrInvalidRequest -32600, ErrMethodNotFound -32601, ErrInvalidParams -32602, ErrInternal -32603; plus `ErrServerBusy = -32099` — a stable transport-local overload response, outside the JSON-RPC reserved range, carrying no peer data.
- `ErrorObject{code, message, data?}` is the wire error object; `RPCError{Code, Message, Data any}` lets a handler choose its error response (rpcwire applies no product redaction — callers must keep Message/Data safe); `ResponseError{Code, Message, Data RawMessage}` is what Conn.Request returns on a peer error (Data stays raw for the protocol adapter).
- `FrameTooLargeError{Direction, Size, Limit}`: "rpcwire: %s frame is %d bytes; limit is %d" (Size/Limit include the trailing newline). `OutboundQueueFullError{Limit}`: TryNotify could not enqueue a best-effort notification without blocking ("rpcwire: outbound notification queue is full (limit %d)") — the caller may drop the event. `WriteStallError{Direction, Size, Stall}`: an outbound write made no progress within MaxWriteStall — transport-fatal, the connection fails so a wedged peer is torn down.

### 13.2 Frame reading (framing.go, bootstrap.go)

- `readLine`: reads until newline through buffer-full continuations, enforces the inbound byte budget mid-accumulation (FrameTooLargeError Direction "inbound"), strips trailing CR/LF and trims surrounding space/tab/CR/LF.
- `ReadStrictRequestFrame` (bootstrap proxy support): reads exactly one request while retaining the reader and buffered remainder for forwarding; keeps `Raw` (exact bytes incl. line ending + harmless whitespace) so a bootstrap proxy can forward unchanged; requires the frame be a strict request with non-empty method and id. `ResponseIDForError` returns an ID safe for an error response — missing/invalid IDs become `null`; valid string, integer, and null IDs are kept (invalid request IDs must never be reflected back).

### 13.3 Conn (conn.go) — one bidirectional JSON-RPC 2.0 NDJSON connection

- Options: MaxInboundBytes, MaxOutboundBytes (non-positive = unlimited; adapters should always set inbound for untrusted peers), Name, `StrictJSONRPC` (validates the jsonrpc member and mutually exclusive frame shapes; Extension Protocol peers always enable it), MaxConcurrentHandlers (default 64; overload requests get ErrServerBusy "server busy"), MaxQueuedNotifications (ordered delivery through one bounded FIFO worker; a full queue FAILS the connection instead of silently losing a notification; non-positive = concurrent best-effort dispatch), `BeforeRequest` (synchronous on the read loop after strict validation, before handler scheduling — lets a protocol atomically record wire arrival order, e.g. initialize-first; error rejects only that request), `BeforeNotification` (synchronous; error silently rejects the notification per JSON-RPC), `MaxWriteStall` (bounds unprogressing writes; stdio peers should always set it — a wedged child otherwise hangs every caller).
- Strict frame validation (`validateStrictFrame`): jsonrpc must be "2.0"; id must be a string, integer, or null; a request (has method) must not carry result/error, and params (if present) must start with { or [; a response must have id, must not have params, must have exactly one of result/error; an error object requires code and message. Malformed JSON → -32700 "parse error"; valid JSON failing strict validation → -32600 "invalid request"; unregistered method → -32601 "method not found: <method>"; handler error mapping: *RPCError uses its code/message/data, otherwise -32603 with err.Error().
- Exactly one writer goroutine owns the writer, fed by the bounded writeQ (`writeQueueLimit = 256` queued outbound frames): two frames can never interleave even when a caller aborts mid-flight; the writer skips frames whose caller gave up before the physical write began and finishes any frame it started (frames are atomic and ordered by construction). Best-effort notifications get a separate `bestEffortNotifyQueueLimit = 16` slot pool so observation events cannot fill the shared queue ahead of blocking intercept/provider/UI/shutdown calls.
- `writeAll` marks progress before every blocking Write for the stall watchdog; caller cancellation never tears a frame in half. `stallWatchdog` fails the connection with WriteStallError when a physical write makes no progress for MaxWriteStall — deliberately independent of any caller context (a short per-call timeout cannot preempt it); ticks at MaxWriteStall/2.
- Outbound encoding: `json.Encoder` with `SetEscapeHTML(false)`; outbound frame over budget → FrameTooLargeError Direction "outbound" BEFORE enqueue; error responses that exceed the frame limit degrade to `-32603 "error response exceeds frame size limit"`.
- `Notify` (blocking write) vs `TryNotify` (non-blocking enqueue; nil = the bounded writer accepted the frame, not that the peer processed it; queue full → OutboundQueueFullError so observation-only callers drop the event instead of adding sidecar backpressure to a host hot path).
- `Request`: marshal params, take int64 id from `nextID` (1-based, atomic), register pending channel, write, wait for response/cancel/closed. A caller-context abort (turn cancel, per-call timeout) fails only that request — the connection stays usable; genuine transport failures (incl. a MaxWriteStall stall) fail the connection. `resolve` parses the response id and delivers; ResponseError carries the peer's structured error.
- Handler responses may be `HandlerResponse{Result, AfterWrite func(error)}`: the callback runs exactly once with the result frame's write error, after a successful response write — transport-local cleanup only, must be fast, must not write to the same Conn (e.g. acknowledge detach before releasing connection ownership). A panic in the callback fails the connection ("after-response callback panic").
- Dispatch concurrency: inbound requests are bounded by handlerSlots (ErrServerBusy when exhausted); notifications run through notifyQueue (FIFO ordered) when configured, else concurrent best-effort. `Serve` reads until EOF/cancel/framing error; in-flight handler contexts are cancelled when the transport ends (work that must outlive the connection must derive from the caller's own runtime context); a completed write racing teardown prefers the buffered result over the terminal error.
- Shutdown (`closeOnce`): records the terminal error, linearizes closure against producers via writeGate, closes writeQ, waits up to `writerExitWaitBound = 100ms` for the writer, closes the closed channel, and fails all pending requests (graceful EOF surfaces as "<name>: connection closed" — terminalError is never nil so dropped writes never look like successes). `fail` also closes the reader.

## 14. sidecar/ — host half of Extension Protocol v2 (internal/ext/extension/sidecar/)

### 14.1 Package contract (doc.go)

- sidecar is the host half: spawns extension sidecar processes, runs the initialize handshake, serves their Extension → Host calls (content reads, UI, provider streams), owns bounded shutdown and crash supervision.
- AUTHORIZATION INVARIANT: a sidecar may only ever be launched for a plugin package present in the pluginpkg installed state (<Reasonix home>/plugin-packages.json) AND currently enabled. The launch API (Manager.StartPackages) takes the pluginpkg installed state as its only input — no way to point it at an arbitrary binary or a runtime declared by project config. Project configuration can declare MCP servers, hooks, and skills, but NEVER a v2 runtime; keeping the invariant by construction is why StartPackages accepts a home directory and loads the state itself instead of caller-supplied command specs.
- FULL-TRUST CONTRACT: a sidecar inherits the UNFILTERED Reasonix environment (os.Environ), plus its manifest env and REASONIX_PLUGIN_ROOT / REASONIX_PLUGIN_NAME / REASONIX_PLUGIN_VERSION. Sidecars can read credentials, the session, and the workspace and act with the user's full authority (the contract an installed v2 runtime accepted at install time, pluginpkg.RuntimeTrustText). Sidecar stderr is redacted in this layer; provider errors, structured UI, and interceptor reasons are redacted again by host-side consumers; ordinary provider/model content remains unchanged as product data.

### 14.2 Manager (manager.go)

- `maxConcurrentPackageStarts = 4` (process creation bound; one slow optional runtime cannot serially delay every later package); `packageStartupBudget = defaultHandshakeTimeout` — shared by every runtime in one generation (N stalled optional runtimes cannot delay boot by N× the per-client handshake timeout).
- `RequiredStartError{Plugin, Err}` — "required extension runtime %q failed to start: %v" — fails the whole build; an optional package's failure is only a warning: "%s: optional extension runtime failed to start: %v".
- `LoadRuntimePackages(home)` / `LoadRuntimePackagesFor(home, workspace)`: enumerate installed+ENABLED packages declaring a native runtime (Manifest.Runtime != nil) — the only enumeration the Manager ever launches from; plus an optional `PackageSource` hook (`SetPackageSource`) contributing host-derived runtimes (e.g. a Claude Code mod becomes a runtime); the source sees only the installed state so it cannot launch anything the user did not install. `OnCrash` observer hook for unexpected sidecar deaths.
- `startLoadedPackages`: handler binding serial; process startup + handshakes through a bounded worker pool (min(4, jobs)) on the caller's shared generation context; results consumed in package order so warnings/required-failure selection do not depend on goroutine completion order. A required package's start failure → RequiredStartError (first one), manager closed. Per-client UI is `UIBinder.HandlerFor(pluginID)` when the UI handler implements UIBinder; OnCrash callback logs "extension sidecar crashed" (slog.Warn, secrets.RedactError), notifies crashObservers + binder.ClientCrashed(pluginID).
- `Manager` owns every sidecar of one runtime generation (io.Closer, retired with its controller generation by RuntimeSet): `Client(pluginID)`, `Clients()` (sorted by plugin ID), `Close()` idempotent — cancels lazy pending starts and waits, shuts every sidecar down in parallel (each client's own budgets bound the total), removes private roots.
- Declaration payloads (kernel contributions): `InterceptorDecl{PluginID, Point, Priority}` (KindInterceptor), `StrategyDecl{PluginID, Slots}` (KindStrategy; implements extension.SlotClaimer via `ReplacementSlots()` so two runtimes claiming the same slot fail the build through ReplaceClaims), `ProviderDecl{PluginID, Descriptor}` (KindProvider), `UIActionDecl{PluginID, Decl}` (KindUIAction).
- `Contributions()` renders every started client's declarations as kernel contributions (ContributionSource{Scope: ScopePlugin, PluginID, Version, Origin: "extension-runtime"}): interceptor stubs per manifest intercept, strategy claims per manifest replaces, provider/UI-action declarations from the validated handshake. Kernel-invalid IDs are SKIPPED with a debug log rather than failing the snapshot: interceptor points and replacement slots and UI action IDs via `kernelID` (non-empty after trim, no space/tab/newline); provider refs must strip the `plugin/<pluginID>/` prefix and pass `extension.IsProviderRef`.

### 14.3 Process spawn and supervision (process.go, exec_format_*.go)

- Bounded-close budgets (mirrored from internal/ext/plugin's stdio transport): `gracefulCloseWaitBudget = 750ms` (stdin-EOF grace for protocol-aware sidecars), `closeWaitBudget = 5s` (hard tree kill + bounded reap — one wedged sidecar can never stall teardown); `stderrTailBytes = 16<<10` (stderr ring buffer bound).
- Sidecar env vars: `REASONIX_PLUGIN_ROOT` (package root), `REASONIX_PLUGIN_NAME` (installed name), `REASONIX_PLUGIN_VERSION` (installed version, falling back to manifest version). runtimeEnv: unfiltered os.Environ() + manifest env + identity variables; later entries win (exec.Cmd.Env semantics) so the manifest can tune but cannot forge the identity variables.
- Exec-form contract (`resolveRuntimeCommand`): expands the REASONIX_PLUGIN_ROOT placeholder (dollar-brace form) via pluginpkg.ExpandRuntimeCommand; the resolved command must be an ABSOLUTE path to the extension executable itself (never a relative name — no PATH lookup; "runtime command %q is not an absolute path after expansion (use %s to address the installed package)"), never a shell — `shellExecutables` = sh, bash, zsh, fish, dash, ksh, cmd, cmd.exe, powershell, powershell.exe, pwsh, pwsh.exe ("runtime command %q is a shell; the runtime contract is exec form (the command is the extension executable, args are its argv)"). Never goes through a shell: exec.Command takes the resolved executable + argv directly; `proc.HideWindow(cmd)`.
- `startupFailure{Stage, Elapsed, Stderr, Err}`: "extension sidecar startup %s failed after %s: %s" (+ "; stderr: <redacted tail>"), stage empty → "unknown", stderr credential-redacted (secrets.RedactCredentials), Err wrapped (Unwrap). Stages: resolve, pipes, spawn. `ErrRuntimeNotExecutable` ("runtime command is not an executable program") — OS refused the program (e.g. a shell script on Windows): on Windows `notExecutableFormat` checks ERROR_BAD_EXE_FORMAT (errno 193), elsewhere syscall.ENOEXEC; message adds "%q cannot be started directly here, so the plugin has to ship a native executable for this system".
- `tailBuffer`: bounded ring of the most recent stderr bytes; writes never block the child; only the tail is surfaced, only after credential redaction.
- `process`: spawned sidecar with pipes + `proc.TrackedJob` (process-tree handle). `wait()` exactly once (sync.Once; safe to abandon — first caller owns cmd.Wait), then `finishJob()` releases the Windows Job Object (handle owns its own one-shot). `kill()` terminates the whole tree via job. `close()` idempotent, never blocks longer than 750ms + 5s: close stdin → short EOF grace → if still alive, kill tree → bounded reap.

### 14.4 Client connection: handshake gate, content store, externalization (client.go, content.go, externalize.go)

Lifecycle budgets (client.go):
- `defaultHandshakeTimeout = 30s` (extension/initialize round trip), `defaultShutdownRequestTimeout = 5s` (extension/shutdown before the bounded process close takes over), `queuedNotifications = 256` (ordered provider-chunk notification queue; full queue FAILS the connection, never drops), `defaultWriteStallBound = 10s` (sidecar alive but not reading stdin → connection fails, process killed), `maxInterceptTimeout = 60s` ceiling (every sync-intercept budget clamped, including manifest overrides), `fastInterceptTimeout = 5s` (input/tool/permission points), `slowInterceptTimeout = 30s` (session/context/system-prompt/compaction family + any unknown point).
- `UIHandler` interface serves Extension → Host UI calls (Publish/Request); `UIBinder` (implemented by the stage-8 UI hub) adds `HandlerFor(pluginID)` per-client bindings + `ClientCrashed(pluginID)`. The nil default `unavailableUIHandler` answers both methods with frozen `unknown_method` reason, message "extension UI is not available on this host" — an extension depending on UI degrades loudly instead of blocking forever.
- `StreamRouter` interface (RouteStreamChunk/RouteStreamEnd); providerext installs the real router via `SetStreamRouter` (nil restores the drop-with-debug-log default). Swap is safe while notifications are in flight.
- `ClientOptions`: Package/Installed (Manifest.Runtime non-nil required), Session context (session ID + workspace root required), UI, Streams, OnCrash (fires exactly once), UIHostKind (empty → headless), HandshakeTimeout (0 → 30s), WriteStallBound (0 → 10s).

StartClient and the handshake state machine:
- `StartClient`: validate → `startProcess` → `newClient` → supervise goroutine → `handshake`. On handshake failure: kill the tree, bounded reap (`closeWaitBudget`), wait serveExited bounded, return `startupFailure{Stage: "handshake"}` — process never outlives a failed start.
- `handshakeState`: new → ready | poisoned | shutdown. The host sends `extension/initialize` FIRST (its only opening move); ANY Extension → Host request or notification before the handshake completes POISONS the connection (`beforeRequest`/`beforeNotification` run on the read loop so the gate observes wire arrival order): state → poisoned, the violation recorded, process killed so a pending handshake unwinds immediately instead of waiting out its timeout; the gate answers with the frozen `protocol_error`. A poisoned handshake returns the violation ("... sent request %q before extension/initialized") in its error.
- Handshake success path: decode + `validateHandshakeResult` → state ready + initResult stored → `Notify(extension/initialized)`.
- `validateHandshakeResult` enforces the declaration contract: protocol version via CompareProtocolVersion; every `subscriptions` entry ⊆ manifest `runtime.intercepts` else `capability_not_declared` "extension %s subscribed to %q which its manifest does not intercept"; every `replaces` ⊆ manifest `runtime.replaces` ("... replaced %q which its manifest does not declare"); `providers` require the manifest `providers` capability and every ref must carry the `plugin/<pluginID>/` prefix ("... declared provider ref %q outside its %q namespace"); `uiActions` require the `ui` capability; dynamic tools + tools validated (see §14.5); manifest `provides` is the capability CEILING — the handshake must not claim capabilities the package never declared (`validateProvidesCeiling`), while declared-but-missing provides stay Unavailable (no forge).
- `readyErr()` gates every outbound call: crashed → `provider_interrupted` "extension sidecar <id> crashed"; shut down → `provider_interrupted` "extension sidecar <id> is shut down"; otherwise (new/poisoned) → `protocol_error` "extension sidecar <id> is not initialized".
- `supervise`: runs the read loop (`conn.Serve`); on end reaps the zombie promptly (`go proc.wait()`); orderly only when state was already shutdown; unexpected end → crashErr (serve error or "extension sidecar exited"), KILL the tree (the process can be alive but unreachable — a wedged reader whose pipe writes stalled), `crashed` flag set, `onCrash` fired exactly once (crashOnce, only if the handshake had completed). `Disconnected()` exposes the serveExited channel — provider stream watchers select on it to finish in-flight streams instead of hanging on notifications that will never arrive.

Outbound call surface (each gated by readyErr; peer errors through `mapRequestError`):
- `Intercept`: blocking `extension/intercept` with `InterceptParams{Event, Seq (per-client atomic uint64, 1-based), Payload, TimeoutMillis}`; timeout defaults to `TimeoutFor(point)` (manifest `runtime.timeoutMillis` clamped to the 60s ceiling; else 5s for input.receive/tool.before/tool.after/permission.decision, 30s for everything else). Deadline expiry with parent context alive → optional `KillOnTimeout` manifest flag kills the process, and the frozen `intercept_timeout` "extension %s did not answer %s within %s". Result replacement externalized → paged back + verified (below).
- `TryNotifyEvent` (`NotifyEvent` is the same call's compat spelling): non-blocking `extension/event` enqueue; queue saturation DROPS the observation (never propagates sidecar backpressure into the agent hot path).
- `NotifyResourcesChanged`: `extension/resources/changed` with paths.
- `UIAction` / `UISubmit`: `extension/ui/action` / `extension/ui/submit` requests (host UI hub routes /<plugin>:<action> invocations and form submissions here).
- `ProviderCatalog`: `extension/provider/catalog` — result carries descriptors only, NEVER credentials.
- `ProviderStreamOpen` / `ProviderStreamCancel`: stream/open request; cancel is best-effort with its own 2s timeout, errors ignored (a wedged or dead sidecar simply never answers inside the bounded budget).
- `Shutdown` (idempotent via shutdownOnce): state → shutdown (unless poisoned); if the handshake completed and not crashed, send `extension/shutdown` {TimeoutMillis} bounded by the given timeout (0 → 5s; errors ignored), then `proc.close()` (stdin → 750ms EOF grace → tree kill → 5s reap), then wait serveExited bounded. Always returns nil. `Close()` = Shutdown(5s).
- Inbound handlers registered on the connection: `host/content/read` → store ReadHandler; `host/ui/publish` / `host/ui/request` → UIHandler via mapHandlerError; `host/session/read` / `host/prompt/submit` (see §14.5 session_calls.go); notifications `extension/provider/stream/chunk` + `extension/provider/stream/end` → StreamRouter (malformed → debug log drop).
- `mapRequestError`: a peer `ResponseError` keeps its frozen reason when the data parses as valid `ProtocolErrorData` (message credential-redacted via secrets.RedactCredentials); invalid or absent protocol data preserves the transport code + raw data but the message is STILL redacted — an untrusted peer message never bypasses the host's redaction boundary. `mapHandlerError`: ProtocolError → RPCError; rpcwire.RPCError passthrough; anything else → frozen `internal`.
- Client facts: version = installed version, falling back to manifest version; `Required()` = manifest `runtime.required`; `TightenOnly()` = manifest `runtime.tightenOnly` (permission rulings may only make a decision stricter); `Exited()` reports the process reaped.

Content store (content.go):
- Per-client, in-memory, session-scoped only — refs expire with the connection, which is exactly why an unknown ref answers the frozen `content_ref_expired`. `storeMaxEntries = 64` objects; past the cap the OLDEST is evicted so a chatty sidecar cannot grow host memory without limit.
- `Put`: rejects objects above `protocol.ContentRefObjectBytes` with frozen `frame_too_large`; ref = "content_" + 12 random bytes hex (24 chars, crypto/rand); stores data copy + SHA-256 hex + insertion order. `Read(ref, offset)`: unknown ref OR offset < 0 OR offset > len → `content_ref_expired`; returns one chunk of at most `protocol.ContentRefChunkBytes`, next offset (nil on final chunk), total bytes, digest. `ReadHandler` serves `host/content/read`: decode failure → frozen `invalid_params`; result `ContentReadResult{ContentRef, Offset, DataBase64, NextOffset, TotalBytes, SHA256, Encoding: utf8}`.
- `MaybeExternalize(store, field, value)`: below `protocol.ExternalizeFieldBytes` → nil descriptor (caller keeps value inline — small calls stay byte-identical); above → store.Put + `ExternalizedField{JSONPointer, ContentRef, TotalBytes, SHA256}`.

Outbound externalization (externalize.go):
- `externalizePayload`: an over-threshold field travels as JSON null in its owner document, and the owner's `externalized` envelope carries one descriptor per moved field naming the ref to page back through host/content/read. Applied to `/payload` of InterceptParams and EventParams via `externalizablePointer` — the pointer set comes from the schema registry; a field absent from `protocol.ExternalizablePointers` fails loudly ("sidecar: %s has no externalizable %s field (schema drift)") instead of silently externalizing a field the schema no longer marks.
- `resolveExternalizedReplacement` (intercept answers): no envelope → inline as-is. Envelope + non-null inline replacement → frozen `protocol_error` "intercept result carries both an inline replacement and an externalized envelope". Envelope must hold EXACTLY ONE descriptor whose JSONPointer is `/replacement`. `TotalBytes` above the object cap → `frame_too_large` "externalized replacement is %d bytes, above the %d byte object cap". The ref is paged back with the exact host/content/read chunking (`Store.readAll`), reassembled length must equal TotalBytes ("...reassembled to %d bytes, want %d") and SHA-256 must match ("externalized replacement SHA-256 mismatch") — only then are the bytes substituted for the caller's strict decode: the dispatcher must never decode bytes the peer did not prove. Only the HOST creates refs (host/content/read is registered Extension → Host alone), so a peer handing back a ref always names an object in this connection's host-side store.

### 14.5 Lazy activation for tool-only runtimes (lazy.go)

- `StartLivePackages`: eager-starts every runtime EXCEPT tool-only packages; tool-only ones are deferred and started on first use. `toolOnlyPackage` test: runtime non-nil, NOT required, no intercepts, no replaces, capabilities == exactly ["tools"], manifest provides all kind "tool", and (len(tools) > 0 or dynamicTools). Everything else starts eagerly under the shared `packageStartupBudget`.
- `EnsureReady(ctx, name)` coalesces activation (one `lazyStart` per plugin; waiters share the done channel) and keeps process lifetime with the manager: manager closed → "extension manager closed"; non-lazy managers serve `clients[name]` directly (missing or exited → "extension %s is unavailable"). Lazy path: reload the installed state (+ resolve hook); the package must still exist and (if deferred) still be tool-only, else `retireLiveClient` + "extension %s was removed, disabled or requires a new runtime". A live client is reused only while `livePackageKey` (agentcomposition.Digest of Installed+Manifest) still matches; an eager package that changed → "extension %s changed its startup contract; reload the runtime"; a changed deferred package retires the old client (close immediately when no calls in flight, else mark retired and close on last release) and starts fresh. Deferred start: `startDeferred` under `packageStartupBudget` on the lazy lifetime context.
- `WithReady(ctx, name, call)`: retry loop — EnsureReady, validate the live call, pin `m.clients[name] == client`, count the call lease, run under `callWithLiveLease` (call context cancelled if the lazy lifetime ends), `releaseLiveCall` closes retired clients on last release. `validateLiveCall` re-checks the installed state: name present + livePackageKey match + manager open, else "extension %s changed or was disabled before dispatch".
- `DeferredPackages()`: with a resolve hook, re-enumerates installed tool-only packages (sorted by name); without, the recorded deferred set. `OnDemand()` reports whether the manager is lazy.

### 14.6 Plan-driven adoption (plan.go)

- Component IDs: `PluginComponentID(name)` = "plugin/" + trimmed name; `PluginNameFromComponentID` extracts it back (non-plugin IDs → "").
- `StartPackagesWithPlan`: starts Added/Reloaded packages and adopts Unchanged clients from the previous manager. No plan or no-op with no previous → fresh `startLoadedPackages` of everything. No-op with a previous manager → `adoptAll` (every live client detached from previous and re-registered; nothing restarted). Otherwise: start only Added+Reloaded (count → `SidecarStarts` metric), then for each Unchanged component detach from previous + adopt into the new manager — an Unchanged component with no live client is started fresh (required failure → RequiredStartError; optional failure → warning); adopt failure rolls back. `planAdopted` records only the adopted unchanged clients so rollback can reattach EXACTLY those.
- `RollbackPlanStart(previous)`: undo the ownership transfer — adopted unchanged clients reattach to previous (reattach failure closes the orphan so the process cannot leak), remaining fresh starts closed via m.Close(). Called on any later activation failure so `previous.Close()` after a failed publish never kills still-active packages.
- `Detach(pluginID)` removes without closing; `Adopt(pluginID, client)` takes ownership (closed manager or duplicate ID refused: "sidecar: plugin %q already registered"); `Drain(ids...)` closes + removes the listed clients (leaves others running) — used after publish to retire Removed/Reloaded packages still held by the old generation; `DrainPlan(plan)` drains plan.Removed + plan.Reloaded names. `startOne` wires per-plugin UI via UIBinder.HandlerFor + OnCrash ("extension sidecar crashed" warning + binder.ClientCrashed).

### 14.7 Initialize params and the provides ceiling (provides.go)

- `initializeParams`: ProtocolVersion + ProtocolID, `Manifest` = the host's expectation manifest (below), Session context, DependencySchemaVersion=1, `Capabilities` = HostCapabilities{ContentRefs: true, UIHost: <tui|desktop|acp|headless>, ProtocolVersion, DependencySchemaVersion}.
- `manifestExpectation`: the manifest's own declares sent as the expectation the sidecar must satisfy — Intercepts, Replaces, Capabilities, ToolNames(), Requires → RequirementWire, Provides → CapabilityWire; plus derived lists: provides kind "provider" → `Providers` entries via `capabilityAddress` (namespace trimmed of trailing "/" + id trimmed of leading "/"), kind "uiaction" → `UIActions` entries.
- `validateProvidesCeiling`: handshake `provides` must be a subset of the manifest provides ceiling, matched by namespace/kind/id triple — "handshake provides %q is outside the manifest provides ceiling". An empty manifest provides list disables the ceiling check (v2 capability strings above still apply).

### 14.8 Composition-selected packages with private roots (selected.go)

- `StartResolvedPackages`: starts the caller's authorized session-scoped selection under `packageStartupBudget`; each package's tree is COPIED (os.CopyFS) into a fresh temp root "reasonix-composition-extensions-*", and the runtime spec's `Command`, `Args`, and `Env` values that point INSIDE the package root are rewritten to the private copy (`privatePackagePath`: absolute paths whose Rel(from, value) is local join the private root; "--key=path" prefixed values keep their prefix; relative values pass through). The temp roots are owned by the manager (`privateRoots`, removed on Close). Failure removes the root immediately.

### 14.9 Session access calls (session_calls.go)

- `SessionHandler` is the optional interface a UIHandler implements to serve `host/session/read` + `host/prompt/submit`. Gate order: the runtime must declare the capability ("session.read" for reads, "session.submit" for queued prompts) else frozen `capability_not_declared` "extension %s called %s without the %s capability"; then the host must implement SessionHandler else frozen `unknown_method` "extension session access is not available on this host". Decode failures answer `invalid_params`. Without the interface those calls degrade exactly like UI calls without a hub.

### 14.10 Tools (tools.go, dynamic_tools.go)

## 15. dispatch/ — host-side interceptor dispatcher (2 files)

### 15.1 Dispatcher walk and error policy (dispatch.go)

- Package purpose: walks the kernel's frozen interceptor chain in order, applies each extension's ruling (continue / block / replace, plus allow / deny at permission.decision only), and runs single-owner strategy replacements for the system_prompt, context, compaction, and session_policy slots. Reads only the frozen chain handed to New — per-turn dynamic data never flows back in, so one Dispatcher serves concurrent turns for the life of its snapshot generation.
- `Client` seam (subset of sidecar.Client): `Intercept(ctx, event, payload, timeout)` + `TryNotifyEvent`; timeout 0 lets the sidecar resolve its per-point budget (TimeoutFor).
- `Options`: `Warn` (warnings discarded when nil), `SidecarDown` (once per extension when an optional extension is skipped because its sidecar is not running), `TightenOnly` (runtimes whose permission rulings may only make the decision stricter), `Mods` (live Claude Code mods — full-trust processes the host does not sandbox or observe). `IsMod`/`HasMod` nil-safe accessors.
- `Result`: `Blocked`, `BlockReason` (redacted), `Answer`/`AnswerBy` (only from a block at tool.before), `Ask` (set when a tighten-only runtime puts the call to the user — never by allow or deny; the caller asks even where the host allowed), `Permission *bool` (terminal allow/deny at permission.decision; nil = every interceptor continued and the host decision stands; the CALLER combines it with the host verdict), `Applied` (plugin IDs that replaced the payload, chain order), `Audit` (redacted notes, e.g. extension allow overriding host deny).
- Error taxonomy: `ViolationError` (contract-breaking answer — redacted Detail + typed Cause; "extension %s violated the intercept contract at %s: %s"), `ErrLoosensDecision` ("a tighten-only runtime may only make a permission decision stricter"), `FailureError` (required extension call failure — redacted message, Unwrap keeps the original so errors.As finds protocol.ProtocolError and its frozen reason), `BlockError` (strategy owner blocking), `ErrNoLiveSidecar` ("no live sidecar client").
- `New` deep-freezes chain/replacements/required/tightenOnly/mods at construction (maps cloned); `warned` dedup set is the only mutable state (guarded). `slotOwners` = plugin IDs owning any replacement slot.
- `Intercept` walk: (1) payloadPtr must be a pointer to EXACTLY the point's registered DTO ("dispatch: %s payload must be %s, got %s" — host programming error, always fatal); (2) marshal current payload; (3) capture `hostDecision` from a *PermissionPayload BEFORE the walk (a replace ruling rewrites the payload but the audit note must reflect the decision the HOST made); (4) for each chain contribution with a plugin ID (host-side contributions without one are skipped): resolve client — nil → failure(ErrNoLiveSidecar); call client.Intercept with timeout 0; call error → failure(); ruling checked by `rulingViolation` → violation(); then the decision switch:
  - `continue`: pass current payload to the next interceptor unchanged.
  - `block`: terminal — Blocked=true, BlockReason/Answer redacted, return immediately.
  - `replace`: strictly re-decode against the point's DTO (decodePayload), adopt host-owned state (`adoptReplacement` → AdoptInputContext for input.receive), whole-value `assignPayload` (omitted/zero fields in the replacement do NOT leak the previous value through), re-marshal for the next interceptor, record Applied.
  - `ask`: Result.Ask = true (walk continues; only legal for tighten-only runtimes at permission.decision).
  - `allow`/`deny`: terminal at permission.decision ONLY ("decision %q is only legal at %s" elsewhere → violation); sets Result.Permission; `allow` with hostDecision "deny" appends audit "extension %s allowed the tool overriding the host deny" (redacted). First allow/deny returns.
  - unknown decision → violation ("unknown decision %q") — unreachable through a real sidecar (registry rejects unknown decisions) but fakes/future peers can send anything.
- `rulingViolation`: an `Answer` rides only a block at tool.before ("an answer is only legal with a block at %s"); `ask` only at permission.decision for a tighten-only runtime; a tighten-only runtime at permission.decision may not `replace` (ErrLoosensDecision "it rewrote the payload") or `allow` (ErrLoosensDecision "it answered allow").
- `RunStrategy(ctx, slot, point, payloadPtr)`: unowned slot = no-op keeping the host default; owner's client missing → FailureError{ErrNoLiveSidecar}; `continue` = nil; `replace` = strict decode (decode failure → ViolationError with redacted detail) + assign; `block` → BlockError (redacted reason); anything else → ViolationError "strategy ruling %q is not continue or replace". The owner is required-class by definition: timeout, error, contract violation, or block is fatal to the current operation. Per-tool (`tool:<name>`) and per-provider (`provider:<ref>`) slots are addressed by strategy dispatch, not broadcast.
- `Event(point, payload)`: fire-and-forget broadcast to every chain member at point PLUS the owners of the slots that observe that point (dedup by plugin). Delivery is non-blocking bounded enqueue (TryNotifyEvent); failures and queue saturation are warned once per plugin and never fail or stall the caller ("extension %s dropped the %s event: %s", redacted). Marshal failure of the host payload → warn "dispatch: dropping %s event: marshal: %v".
- `slotsForPoint` (event-broadcast mapping only): system_prompt.build→SlotSystemPrompt; context.prepare→SlotContext; provider.request→SlotProviderRequest; provider.response→SlotProviderResponse; compaction.prepare/complete→SlotCompaction; session.start/end/load/save/rotate→SlotSessionPolicy; permission.decision→SlotPermission; frontend.event→SlotFrontendEvents.
- Required-class = manifest `required:true` OR owner of any replacement slot (`isRequired`). `failure`: required → FailureError (fails the operation); optional → warn once ("extension %s failed at %s; skipping this optional extension: %s", redacted) — the no-live-sidecar case routes through `SidecarDown` once per plugin when provided. `violation`: required → ViolationError; optional → warn once ("...; skipping this optional extension's ruling") and the ruling is skipped. Warn-once keys: "error|", "sidecar|", "violation|", "event|" + pluginID — once per key for the life of the process.

## 16. providerext/ + providerconv/ — extension-hosted provider adapter (3+1 files)

### 16.1 Resolver merge and conflict rule (providerext.go)

- Package mirrors the Remote broker's host-side semantics (internal/platform/remote/broker) exactly: 1-based contiguous seq buffering, bounded delivery queue, gap timer on stream end, cancellation through stream/cancel, interruption via StreamInterruptedError. A selected sidecar's crash fails its streams — the adapter NEVER falls back to a different provider for plugin refs.
- `ProviderClient` seam (satisfied by *sidecar.Client): PluginID, Crashed, Disconnected (channel closed when the serve loop ends for ANY reason), Handshake (declaration of record for routing and conflicts), ProviderCatalog, ProviderStreamOpen, ProviderStreamCancel.
- Conflict rule: a sidecar provider ref identical to a base-catalog ref is legal ONLY when the plugin owns the `provider:<ref>` replacement slot (then the sidecar descriptor REPLACES the base entry); otherwise `ConflictError` — "extension provider conflict: plugin %q declares provider ref %q that the host provider catalog already serves; declare %q in the plugin manifest's runtime.replaces to override it". Boot treats it as fatal, the same class as sidecar.RequiredStartError. Refs outside the plugin's own `plugin/<id>/` prefix are skipped defensively at merge time (handshake already enforced the namespace).
- `Catalog()`: base catalog minus claim-replaced entries, plus every reachable sidecar's catalog. Per-client cache for the client's lifetime; a crashed sidecar's cache is dropped and its entries stop being offered; fetch failure skips that sidecar for the call (best-effort). `catalogFetchTimeout` = 10s. Single-flight `catalogCall`: first caller owns the RPC, followers wait and get defensive copies (prevents duplicate first-use RPCs and last-completion-wins cache contents). Catalog RPC results skip refs outside the plugin namespace.
- `Resolve(selection)`: empty ref → "provider selection ref is required"; non-plugin refs → base resolver; `plugin/<id>/...` refs → the owning sidecar. Plugin not running → "unknown provider ref %q: extension plugin %q is not running"; plugin running but never declared it → "unknown provider ref %q: extension plugin %q does not declare it". `declaredDescriptor`: exact ref match OR broker-style prefix form (ref names a provider, declaration adds the model segment). `PluginRefOwner` re-exports protocol.PluginRefOwner.

### 16.2 Provider handle and stream open (provider.go)

- `Provider` (implements provider.Provider): `Name()` = the ref's first segment ("plugin" for extension refs); `RequiresToolCallReasoning`/`RequiresReasoningRoundTrip` from the descriptor. The effort from the resolving Selection is baked in at construction (like boot bakes effort into local providers). Streams run on the owning sidecar, which holds the credentials: open params carry only the request, the ref, the model, and the effort — the host never sends another provider's keys across the extension boundary.
- `Stream`: re-resolves the live backend each call so rolling replacement keeps the same provider-visible ref (cache-stable); missing resolver/client → "extension provider is unavailable".
- `Resolver.open`: (1) crashed client → StreamInterruptedError "extension sidecar %s crashed"; (2) stream id = "es_" + 12 hex (crypto/rand; fallback UnixNano); out channel 64, nextSeq 1; (3) register the buffered stream BEFORE opening, and register the gate drain-cancel first — a sidecar may emit stream/end or overflow while ProviderStreamOpen is still returning ("Register before opening" comment); drain timeout aborts delivery and finishes with "extension stream %s: generation %d drain timed out" then cancels best-effort; (4) `ProviderStreamOpen` params {StreamID, ProviderRef, Model (descriptor's), Effort, Request (providerconv.RequestToProtocol), SeqBase: 1}; failure → removeStream + best-effort cancel + mapStreamOpenError; (5) `!opened.Accepted` → removeStream + cancel + "extension %s declined provider stream %q"; (6) the provider request is now submitted to the sidecar — `owner.RecordProviderSubmit(gen, id, pluginID)` marks it irreversible for recovery (never claim rollback of an in-flight provider call); (7) `watchStream` goroutine.
- `watchStream`: caller cancellation aborts delivery (consumer is gone), finishes with ctx.Err(), and notifies the sidecar via ProviderStreamCancel; a `Disconnected()` close keeps draining buffered chunks before the terminal "extension sidecar %s disconnected" interruption (broker detach semantics).
- `mapStreamOpenError`: sidecar `provider_interrupted` lifts into StreamInterruptedError (agent interruption recovery applies); every other failure passes through with its frozen protocol reason intact.

### 16.3 Stream routing and delivery (stream.go)

- `extensionStream` mirrors the broker's hostStream: 1-based seqs, out-of-order buffering, contiguous flush; `stream/end` freezes the terminal boundary (LastSeq); gap timer converts a missing tail chunk into an interruption instead of a hang.
- Constants: `deliveryQueueLimit` = 256 (one slot reserved for the terminal chunk; overflow finishes interrupted "extension provider stream output overflow"); `pendingWindowLimit` = 256 (chunks with seq ≥ nextSeq+256 never enter pending — a sidecar sequencing bug must not grow host memory without limit → "extension stream %s: chunk seq %d exceeds the pending window of stream seq %d").
- `RouteStreamChunk` (sidecar.StreamRouter): stale-generation chunks dropped via owner gate DropStale("provider_chunk") (generation from params or chunk, 0 tolerated); unknown stream ID dropped with debug log (a sidecar can legitimately race a late chunk against the host's cancel or its own crash teardown); `seq < nextSeq` = duplicate/already delivered, silently skipped; ended and `seq > endSeq` → interrupted "chunk seq %d exceeds frozen LastSeq %d".
- `RouteStreamEnd`: LastSeq freezes the boundary; the stream completes only after chunks 1..LastSeq are delivered. A second end with a DIFFERENT LastSeq/Error/Interrupted → interrupted "conflicting duplicate end changed frozen LastSeq or terminal state"; an identical duplicate just re-flushes. A buffered pending chunk beyond endSeq → interrupted "buffered chunk seq %d exceeds frozen LastSeq %d".
- `flushLocked`: delivers contiguous pending chunks; on complete boundary: reported error defensively credential-redacted even though the protocol also requires producer-side redaction; interruption becomes StreamInterruptedError (empty message defaults: "extension provider stream failed" / "extension provider stream was interrupted"); clean end closes with a zero terminal chunk.
- `finishLocked`: first finish wins (map identity check + closeOnce); unregisters the drain-cancel; terminal chunk appended when non-zero. `deliverStream` is the SOLE sender and closer of stream.out — it may wait for a slow consumer but never while holding Resolver.mu, so routing, cancellation, disconnects, gap expiry, and unrelated streams keep moving. `expireGap`: 1s timer after stream/end → "extension provider stream missing chunk %d of %d".

### 16.4 Host↔wire conversions (providerconv/providerconv.go)

Wire DTOs never carry credentials: ProviderError messages must be redacted by the producer before crossing, and the host defensively redacts again at the trust boundary.

## 18. Root package — runtime model core (28 files)

### 18.1 Builder pipeline and conflict policy (builder.go)

- `Activator` binds live resources (MCP sidecars, watchers) to a freshly frozen snapshot; nil *RuntimeSet is an empty set bound to the snapshot's generation.
- `Builder` assembles a RuntimeSnapshot through a fixed linear pipeline: Discover → Parse → Validate → Resolve → Assemble → Freeze → Activate. Registration order never influences the snapshot — catalog, winner rules, and interceptor chains all sort on contribution data, not arrival order. `WithSystemPrompt` participates in CacheHash (part of the provider-visible request prefix). `WithGeneration` pairs with RuntimeSet.CloseIfGeneration so stale cleanup cannot close a newer runtime's resources.
- `ConflictPolicy`: `ConflictFail` (default; v2 extensions) — a disputed same-tier canonical ID claimed by distinct sources aborts the build with ConflictError ("a package must never silently override another package's capability"); `ConflictCollect` (boot's legacy assembly) — keeps the deterministic winner (highest tier, then first registration) and records the dispute on the snapshot's Diagnostics instead of failing (those resources already resolved clashes inside their own discovery passes; a residual dispute must never change whether a session boots). Malformed contributions still fail validation and replacement-slot disputes still fail resolution under BOTH policies — only shadowing conflicts are collected.
- `ValidationError`: validation collects ALL malformed contributions in one pass ("extension: invalid %s %q: %s"). Per-contribution rules: unknown kind; empty ID; ID contains whitespace; unknown scope; kind-specific — tool IDs must be lowercase, `mcp__<server>__<tool>` well-formed when prefixed, MCP-metadata payloads must live in the mcp__ namespace ("MCP tool IDs must start with mcp__"), payload must be tool.Tool / tool.ContractEntry / provider.ToolSchema; provider IDs must be a `<name>/<model>` ref; interceptor IDs must be known points with `ValidatePriority`-valid priority. `ValidToolID` exports the ID-shape half for legacy-registry wrappers.
- `toolSchemaOf` renders a tool payload into a provider schema and canonicalizes parameters ONCE here, so every consumer (including CacheHash) sees identical bytes regardless of how the contributor marshaled them.
- `resolveContributions` winner rules: shadowed kinds (tools, skills, commands, MCP servers, providers, prompts, themes, UI actions, strategies) — highest tier wins the canonical ID; distinct sources tied at the top tier are a hard ConflictError under ConflictFail or a recorded conflict under ConflictCollect (same deterministic winner); duplicates from a single source collapse to the first registration (first-root-wins). Hooks and interceptors are additive — every contribution survives, nothing ever conflicts. Replacement claims come from payloads implementing `SlotClaimer` and are collected ACROSS ALL CONTRIBUTIONS, not just winners ("a losing contribution must not silently keep a slot it declared"); a second claimant for a slot is a hard SlotConflictError under both policies.
- `resolveGroup`: winner = lowest Order (first registration) among the highest `tierRank(Source.Scope)`; the disputed check reports the distinct sources. `assemble`: freezes catalog, renders + `normalizeToolSchemas`, groups + `SortInterceptors` chains per point, copies replacements, freezes conflict diagnostics in pipeline (first-appearance) order, `computeCacheShape(systemPrompt, schemas)` → systemHash, toolsHash, cacheHash. `activate` runs the Activator on the FROZEN snapshot (an activator must observe, never mutate); nil result → empty set.

### 18.2 PublishGate — activate → publish → drain (publish.go)

- Only one generation is Published at a time; older generations are Draining and their late traffic must be dropped. `NewPublishGate` default drainTTL 30s (`WithDrainTTL`).
- `Publish(gen)`: previous published generation enters Draining (timestamped); same-generation publish is a no-op; publishing clears the gen's expired marker; DefaultLifecycleMetrics.Publishes+1. `BeginDrain` marks draining WITHOUT moving the published pointer (an un-published activation failed and its resources are disposed). `IsStale(messageGen)`: non-zero and ≠ published. `AdmitNewWork`: when published==0 admit everything; otherwise only the published generation admits (draining generations refuse new turns). `DropStale`: IsStale + StaleDrops metric + onStale callback.
- `SweepExpiredDrains`: removes drain entries older than drainTTL, marks them expired, returns them. `DrainTimeoutError`: "extension: generation %d drain timed out".
- `RegisterDrainCancel(gen, cancel)` → idempotent unregister: remaining callbacks fire once when the generation is force-expired. Late-registration rule: an already-expired generation, OR one below the published generation with no drain/expired marker (its bounded-retention expiry marker already evicted), fires cancel IMMEDIATELY — generation IDs increase monotonically, so such a registration is provably stale.
- `ForceExpireDrain` / `SweepAndForceExpire`: cancel remaining in-flight work, forget the drain, and record `EffectReceipt{ID: "drain-timeout-<gen>", Class: Irreversible, CompensationStatus: "not_applicable", Error: DrainTimeoutError text}`. `ScheduleDrainWatch`: one coalesced background timer while any generation drains (cold publishes allocate no timer goroutine; rapid publishes share one watcher; re-arms while drains remain).
- Expired-generation markers: bounded `defaultExpiredGenerationLimit` = 256, FIFO eviction (`markExpiredLocked`/`clearExpiredLocked`); `Publish` clears the new generation's marker. `DefaultPublishGate()` = the compat owner's gate (RuntimeOwnerOrDefault(nil).Gate; product boot binds an isolated RuntimeOwner instead); package-level RegisterDrainCancel/FireDrainCancels preserve the compat API. `AwaitReady(ctx, ready)` gates publish on component readiness.

### 18.3 RuntimePlan and subgraph classification (runtimeplan.go)

- `SubgraphKind`: None / InterceptorOnly / ProviderOnly / UIOnly / MCPOnly / Sidecar / Full. `RuntimePlan` fields: FromGeneration, ToGeneration, Added, Removed, Reloaded, Unchanged, ActivateOrder, DrainOrder, `PrefixChanged` (observed POST-build fact — boot sets it only after both snapshots exist and their CacheHash values can be compared; graph diffing alone cannot prove provider-visible byte changes), `ProviderChanged` (any changed component provided a provider capability on EITHER side of the transition — keeps provider removal visible), Kind, Graph.
- Predicates: `IsNoOp` (no Added/Removed/Reloaded); `MayChangePrefix` — conservative pre-build signal, false for InterceptorOnly and UIOnly (those plans do not change CacheHash by contract); `AffectsSidecars` (any non-no-op); `AffectsInterceptors` (InterceptorOnly|Full|Sidecar); `AffectsUI` (UIOnly|Full|Sidecar); `AffectsProviders` (ProviderChanged || ProviderOnly|Full|Sidecar).
- `DiffRuntimePlan(from, to, fromGen, toGen)`: per-component Added (new id), Reloaded (componentIdentityChanged OR epochsChanged — required epochs differ), Unchanged, Removed (in from only); all four sorted; ActivateOrder = to.ActivateOrder(); DrainOrder = removed + reloaded, in the OLD graph's DrainOrder() (reverse dependency order).
- `classifySubgraph`: inspects changed components' intercepts/replaces and provides kinds — "provider" → provider, "ui"/"uiaction" → UI, "mcp"/"mcpserver" → MCP, "interceptors"/"strategies" → interceptor, other non-empty kinds → other; plugin/<name> components with empty provides count as other (sidecar); `mcpSchemaChanged` (an MCP capability added/removed or its SchemaHash renamed) forces SubgraphFull so provider-visible tool bytes cannot remain stale — an MCP backend roll stays narrow ONLY while its declared schema shape is unchanged; >1 kind → Full when hasOther else Sidecar; exactly one kind → that subgraph; none → Full.
- `componentIdentityChanged`: Priority, Optional, Source key + Version, Intercepts, Replaces, Provides length + per-entry CanonicalHash, Requires length + per-entry Key/Version/VersionRange/SchemaHash/Optional. `epochsChanged`: a component's Requires epochs resolved differently between graphs (EpochFor comparisons).

### 18.4 Dependency graph (dependency.go)

- `ComponentID` (string) is the stable identity of one lifecycle component; `ComponentState` fixed states: `Inactive`, `Preparing`, `Active`, `Draining`, `Failed`. `ComponentDescriptor` is the immutable graph input (no live handles): ID, Source, Requires, Provides, Intercepts, Replaces, `Priority` (deterministic activation ordering), `Optional` (non-blocking when it cannot activate).
- `ComponentEpoch` is the dependency identity that forces consumer reload when it changes (fiber UIDs alone are not enough): CapabilityKey, ProviderComponentID, ProviderVersion, ProviderSchemaHash; String = `<key>|<provider>|<version>|<schemahash>`.
- `DependencyGraph`: Components map, Edges (consumer → providers), Providers (capability key string → component IDs), Diagnostics. `GraphError`{Reason, Cycle, Detail} renders as `extension: <reason>: <detail>` or with a cycle path joined by ` -> `.
- `BuildDependencyGraph` rejects: empty ID (`invalid_component`), duplicate ID (`duplicate_component`), invalid capability (`invalid_capability`), invalid requirement (`invalid_requirement`). Requirement resolution: no matched provider — optional → diagnostic `optional dependency unsatisfied: <id> requires <key>`; required → `dependency_unsatisfied`. More than one provider for one key without explicit selection → `duplicate_provider`. Required-cycle detection (DFS, sorted node iteration) → `dependency_cycle`. Provider lists and edges sorted for determinism; diagnostics sorted.
- `ActivateOrder()` = deterministic topological order (Kahn's algorithm with a deterministic ready-set sort); `DrainOrder()` = reverse. `EpochFor(consumer, req)` returns the epoch a consumer should pin.
- `componentLess` fixed sort: dependencyRank (number of transitive providers — deeper deps first), then scope `tierRank` DESC ("higher scope rank first so project-owned nodes win ties predictably"), then `Priority` DESC, then canonical component ID ascending. The result is independent of input order.

### 18.5 RuntimeSnapshot (snapshot.go)

- Immutable after Freeze: private fields, every accessor returns defensive copies; snapshots share across turns/subagents/frontends without locking. Two snapshots with equal `CacheHash` are interchangeable for provider caching even when provenance differs.
- `WithGeneration(gen)`: shallow copy advancing generation; CacheHash and provider-visible fields preserved byte-for-byte so a no-op rebuild advances generation without prompt/tool cache churn.
- `WithLiveContributions(gen, live)`: rebuilds interceptor chains and replacement slots from live sidecar contributions while system prompt, tool schemas, and CacheHash stay byte-identical — provider/MCP backend rolls must not churn the provider-visible prefix. Plugin-scoped live kinds (interceptor, provider, ui_action, strategy with ScopePlugin) are ALWAYS dropped, even when `live` is empty (plugin removed). Replacements: keep non-plugin owners, drop all plugin owners, re-apply live strategy claims. Catalog overlay rebuilt so doctor/UI see the live provider/UI contribution set.
- `normalizeToolSchemas` sorts by (name, description, parameters) so reordered input cannot change the hash — mirrors internal/runtime/agent/cache_shape.go, reimplemented (not imported) because the kernel must stay below the agent package in the dependency graph.
- `computeCacheShape`: systemHash = sha256(systemPrompt); toolsHash = sha256(JSON of canonical schemas); cacheHash = sha256(JSON of `cacheHashInput{systemPrompt, toolSchemas}`). `CacheShape()` exposes the two halves so cache-miss diagnostics can say which half moved.

### 18.6 Catalog and conflict detection (catalog.go)

- `ContributionKind` wire names (stable): `tool`, `skill`, `command`, `prompt`, `hook`, `mcp_server`, `provider`, `theme`, `ui_action`, `interceptor`, `strategy` (11 kinds). `knownKind` rejects unknown kinds at validation. `additiveKind` = hook + interceptor only.
- `Contribution`: Kind, ID (canonical within kind — the ID the user or model sees), Source (provenance, Scope drives shadowing), Priority, Payload (the existing concrete type, deliberately not re-wrapped), Order (per-contributor registration sequence stamped by the Builder; makes same-source duplicates deterministic without map/discovery order).
- `Catalog`: `Add` panics on a frozen catalog (`extension: Add on frozen catalog`) — growth past freeze is a wiring bug, not data. All/ByKind/Get return sorted copies. `SortContributions` total order: kind asc, tierRank DESC (effective winner reads first), Priority DESC, PluginID, ID, Order, Origin, Path — final Source tiebreaks make the order total and independent of contributor registration order.
- `ConflictError`: `extension: conflicting <kind> "<id>" claimed by <labels>`. `Catalog.Conflicts()` reports same-tier multi-source duplicates for shadowed (non-additive) kinds only, deterministically ordered. `conflictingSources`: distinct sources tied at the highest tier, deduped by source key (scope|plugin|origin — path excluded so several files from one root count as one source, mirroring first-root-wins).

### 18.7 Per-session sidecar state store (sessionstate.go)

- Store path = session JSONL path + `.extensions.json` (`SessionExtensionsVersion` 1). The store NEVER reads or writes the session JSONL itself; readers that predate extensions ignore the additive file.
- `MaxPluginStateBytes` = 1 MiB (`1 << 20`); `ErrPluginStateTooLarge` = `extension: plugin session state exceeds 1 MiB`. Writes beyond the cap fail — truncating would silently corrupt the extension's state.
- `LoadSessionExtensions`: missing or corrupt file → empty store and no error (extension state must never crash a session load; the next Save atomically replaces the bad file). Decode is strict (DisallowUnknownFields). Over-cap blobs are dropped, not truncated (partial JSON is worse than none).
- `Set`: plugin ID required, blob ≤ 1 MiB and valid JSON (`extension: plugin "<id>" session state must be valid JSON`). `Save`: AtomicWriteFile (tmpfile + rename), 0644, trailing newline, version 1 envelope `{version, plugins}`.

### 18.8 Receipt store (receipt_store.go)

- Process-local bounded ledger: `defaultReceiptGenerationLimit` 32 generations × `defaultReceiptPerGenerationLimit` 256 receipts per generation (retention is not persistence; crash recovery is outside its contract).
- `Record`: Irreversible receipts NEVER claim rollback — CompensationStatus is forced to `not_applicable` when "applied"/"rolled_back"/empty. Empty IDs auto-generate `receipt-<seq>`. An ID reused across generations gets a `#gen-<gen>` suffix (receipt IDs are update keys only within one generation). Zero fields merge from the previous record under the same ID. `trimLocked` evicts whole old generations first, then the oldest receipts of an overfull generation (bucket flagged truncated).
- `generationSnapshot` reports truncation when the bucket was trimmed or the whole generation was evicted. `AssessRecoverability(gen)` → `Recoverability{clean, hasIrreversible, blocking?, notes?}` (JSON camelCase): truncated → clean=false, blocking += `receipt-history-truncated`, note "receipt history was evicted; clean rollback cannot be proven"; irreversible → hasIrreversible, clean=false, note `irreversible effect <id> cannot be rolled back`; compensatable with status failed/empty/prior_truncated → clean=false, blocking += receipt ID, note `compensatable effect <id> not fully compensated`.
- `IngestScope` copies an EffectScope's receipts into the store; `onEvict` hook fires for evicted receipts (the RuntimeOwner uses it to forget file priors for compensatable receipts and message-dedup keys).

### 18.9 RuntimeOwner (runtime_owner.go)

- `RuntimeOwner`{Gate, Receipts, FilePriors, Messages, HostStreams, Notices} owns generation-scoped lifecycle state for one logical controller/session lineage. Rebuilds reuse the owner; independent sessions get independent owners, so publishing one runtime never drains another.
- `NewRuntimeOwner` wires the eviction cascade: receipt onEvict → FilePriors.Forget (compensatable) + MessageSendGuard.ForgetReceipt; HostStreamRegistry bound to the gate.
- `DefaultRuntimeOwner` (compat) + `RuntimeOwnerOrDefault`: a nil owner falls back to the default and increments a process-local counter — `RuntimeOwnerFallbackCount()` makes missed wiring observable in doctor instead of silently sharing state. Context binding: `ContextWithRuntimeOwner` / `RuntimeOwnerFromContext` (fallback counted).
- Recording API: `RecordProviderSubmit` → receipt `provider-submit:<streamID>` (irreversible, not_applicable); `RecordMessageSentOnce` → MessageSendGuard dedup, receipt `message-sent:<messageID>`; `RecordFileWrite` → receipt `file-write:<gen>:<seq>`, CompensationStatus `prior_captured` or `prior_truncated`, Error `prior_bytes=<n> retained=<bool>`; `ApplyFileWriteCompensation` → restore prior (failed → receipt status failed; ok → Forget + applied). `DecideResume`/`AssessRecoverability` are owner-scoped.

### 18.10 EffectScope (effectscope.go)

- `EffectClass`: `Reversible` (fully undone by Dispose), `Cancelable` (stop further work; Dispose waits), `Compensatable` (may run Compensate), `Irreversible` (receipt only; never claim rollback success).
- `Effect{ID, Owner, Component, Class, Dispose, Compensate}`; `EffectReceipt` JSON: id, owner, generation, component?, class, startedAt, completedAt?, compensationStatus?, error?.
- `LiveScope` (default EffectScope): reverse-registration-order, once-only, idempotent Dispose; individual errors joined, never skip remaining effects. `Track` validates: ID required; Dispose required unless Irreversible; duplicate ID rejected. Tracking on a closed scope disposes the effect immediately (activation races cannot leak resources). Receipts are recorded at track time for Irreversible/Compensatable. On dispose: Compensatable runs Compensate (failure → status failed + error `compensate <id>: <err>`; success → applied); Irreversible → `not_applicable`; receipts get CompletedAt.

### 18.11 Replacement slots (replace.go)

- `Slot` names a runtime seam with exactly one owner at a time. Eight named slots (closed set — inventing one in a manifest must fail loudly): `system_prompt`, `context`, `provider_request`, `provider_response`, `compaction`, `session_policy`, `permission`, `frontend_events`. Namespaced forms: `tool:<name>` (SlotTool), `provider:<ref>` (SlotProviderRef).
- `ParseSlot` errors: `extension: invalid tool slot "<s>": empty or whitespace tool name`; `extension: invalid provider slot "<s>": want provider:<name>/<model> or provider:plugin/<plugin>/<name>/<model>`; `extension: unknown slot "<s>"`.
- `SlotClaimer` interface (`ReplacementSlots() []Slot`) — the kernel enforces single ownership at resolve time; legitimacy (claims ⊆ declared) belongs to the caller at contribution time. `SlotConflictError`: `extension: replacement slot "<slot>" claimed by <labels>`. `ReplaceClaims.Claim` validates via ParseSlot and names both owners on the second claim.

### 18.12 Scope resource helpers (scope_resources.go)

- Fixed-effect-ID Track helpers: `TrackMCPClient` (`mcp-client:<serverName>`, reversible), `FuncCloser` adapter, `TrackUIHub` (`ui-hub-gen-<gen>`, reversible, no-op dispose — hub reused across generations), `TrackProviderStream` (`provider-stream:<id>`, cancelable: cancel then wait), `TrackWatcher` (`watcher:<id>`), `TrackEventSubscription` (`event-sub:<id>`), `TrackBackgroundJob` (`bg:<id>`, cancelable), `TrackControllerCleanup` (`controller-cleanup:<id>`), `TrackIrreversible` (records a receipt into the default owner's Receipts, not_applicable).

### 18.13 Interceptor points and ordering (intercept.go)

- 17 frozen `InterceptorPoint`s: session.start, session.end, session.load, session.save, session.rotate, input.receive, agent.before_start, system_prompt.build, context.prepare, provider.request, provider.response, tool.before, tool.after, permission.decision, compaction.prepare, compaction.complete, frontend.event. Unknown points are rejected at validation (a misspelled point would sit unused and its author would never notice).
- `ValidatePriority`: bounds `[-1000, 1000]`; error `extension: interceptor priority <p> out of range [-1000, 1000]` (unbounded priorities would let one contributor squeeze ahead of every future interceptor).
- `SortInterceptors`: ascending priority (lower runs earlier), then PluginID (one package's chain contiguous), then per-contributor Order, then ID/Origin tiebreaks; input not mutated, sorted copy returned.

### 18.14 Lifecycle registry (lifecycle.go)

- `LifecycleRegistry` tracks component states for one published generation; diagnostic-first (doctor/UI read it, activation advances via Transition).
- Legal transition matrix: Inactive→Preparing|Failed; Preparing→Active|Failed|Inactive; Active→Draining|Failed; Draining→Inactive|Failed; Failed→Inactive|Preparing; same→same always legal. Illegal transition → error `extension: illegal lifecycle transition <id>: <from> -> <to>`, state unchanged. `Fail` records the error text. `RuntimeStatus(plan, receipts)` builds the host-facing status document.

### 18.15 MCP proxy (mcpproxy.go)

- `MCPBackend` = Backend + `Call(ctx, toolName, args []byte) ([]byte, error)`. `MCPProxy` is the stable consumer-facing handle for one MCP server name wrapping a StableProxy: tool schemas and provider-visible prefix stay owned by RuntimeSnapshot; only the live process/connection swaps. `Call` fails fast when no backend is registered (crash/replace window); in-flight calls cancel on Replace/Close. `MCPProxySet`: named registry, Get creates on demand, Close drains every proxy.

### 18.16 Host stream registry (host_stream.go)

- `HostStreamRegistry` tracks host-side provider streams (OpenAI/Anthropic/etc.) so generation drain can cancel in-flight HTTP reads without waiting for controller.Cancel of a still-published generation. `Track(gen, cancel)` → untrack (once-safe); gen 0 → no-op. One drain hook per generation fans a single RegisterDrainCancel into `CancelGeneration(gen)` (registered outside the registry mutex because an already-expired generation fires synchronously).

### 18.17 File priors and compensation (file_compensate.go)

- `FilePriorStore`: in-process prior-content store for compensatable write_file receipts. Budgets: `defaultFilePriorMaxBytes` 32 MiB per owner, `defaultFilePriorMaxEntryBytes` 8 MiB per entry — Capture returns false beyond either (recovery then reports prior_truncated and stays conservative).
- `Compensate(id)`: file did not exist → os.Remove (IsNotExist tolerated); existed → MkdirAll 0755 + WriteFile 0644 of the prior content. `Forget` after successful compensation. Package-level `ApplyFileWriteCompensation` goes through the default owner.

### 18.18 Scope tiers and provenance (source.go)

- `Scope` wire names are stable (they appear in manifests, diagnostics, conflict reports — a rename is a protocol break): `builtin`, `global`, `project`, `plugin`, `claude_compat`, `codex_compat`.
- `tierRank`: project 60 > claude_compat 50 > codex_compat 40 > plugin 30 > global 20 > builtin 10 > unknown 0. Unknown scopes rank below builtin so they LOSE every shadow race instead of accidentally winning one; the builder rejects unknown scopes at validation anyway.
- `ContributionSource`{PluginID, Version, Origin, Scope, Priority, Path}: source key = scope|plugin|origin (path excluded — several files discovered by one root count as one source, mirroring first-root-wins); label prefers `plugin <id>` because cross-plugin conflicts are the ones users must act on. Path is diagnostic-only and never influences winner rules.

### 18.19 StableProxy — backend roll (proxy.go)

- `Backend` interface: `ID() string`, `Close(ctx) error` (drains in-flight work). `StableProxy` presents a stable consumer-facing handle while backends roll; it never alters provider-visible prompt/tool prefixes (cache identity stays owned by RuntimeSnapshot.CacheHash).
- `Replace(ctx, next, generation)`: closed proxy → error `extension: proxy closed` (the new backend is still closed). Swap active, record generation, cancel all in-flight CallCtx work, then drain the previous backend (error wrapped `drain previous backend: <err>`). `Close`: CAS on closed, cancel in-flight, close active then draining. `CallCtx`: no active backend → `extension: no active backend`; call context is cancelled when the proxy is Replaced or Closed. `CancelInFlight` aborts every outstanding call (generation drain).

### 18.20 Discovery adapters (adapters.go)

- Each function maps one already-discovered record onto one Contribution; a source's own intra-source winner rules (skill tier priority, command later-root-wins, hook accumulation) run in the source package before records arrive — the kernel resolves only what crosses contributor boundaries.
- `SkillContribution`: canonical ID = the user-facing slash name, so a plugin skill (`pkg:name`) and a project skill (`name`) occupy distinct IDs exactly as they do for the user. Scope mapping: plugin → ScopePlugin (plugin ownership wins over discovery scope); project/builtin map directly; custom roots → ScopeGlobal (custom has no kernel tier; the store's own project > custom > global ordering already ran inside List).
- `CommandContribution`: non-plugin commands map to ScopeProject origin `command_root` (command.LoadRoots already collapsed user-vs-project into one winner); plugin commands → ScopePlugin.
- `HookContribution`: additive; ID = `<event>#<seq>` where seq is the per-event load index, matching the order hooks fire today (project, then plugin, then global within an event).
- `MCPServerContribution`: ID = spec.Name — the same identity that namespaces the server's tools as `mcp__<server>__<tool>`. Scope: spec.Package or ConfigSource `plugin_package` → ScopePlugin; ConfigSource prefix `project` or `workspace_config` → ScopeProject; else ScopeGlobal (default origin `user_config`).
- `ProviderContribution`: ID = descriptor ref (`<name>/<model>`), ScopeBuiltin, origin `provider_catalog`.

### 18.21 Lifecycle metrics (metrics.go)

- Process-wide atomic counter set (anonymous tallies only, no content): publishes, drains, staleDrops, admissionRejected, noOpRebuilds, fullRebuilds, subgraphRebuilds, sidecarAdopts, sidecarStarts, plus cumulative nanos + counts for activate/drain/graphBuild/planDiff. `Snapshot()` returns a JSON-camelCase copy with averaged timings (activateAvgNanos, drainAvgNanos, graphBuildAvgNanos, planDiffAvgNanos).

### 18.22 Message-send dedup (message_dedup.go)

- `MessageSendGuard`: `TryRecord(gen, messageID)` true only on first observation of the (generation, messageID) pair; key `<gen>:<messageID>`. `ForgetReceipt` keeps dedup retention aligned with ReceiptStore eviction: receipt IDs with prefix `message-sent:`, messageID from Component (or the trimmed ID minus the `#gen-<gen>` suffix). Package-level `RecordMessageSentOnce` via the default owner.

### 18.23 Recovery policy (recovery_policy.go)

- `ResumeDecision` JSON: `{allowResume, cleanRollback, hasIrreversible, notes?, blocking?}`. AllowResume is always true when the process is healthy enough to continue (external side effects may already have happened); CleanRollback is true only when no irreversible work completed AND all compensatable work finished compensation successfully. `DecideResume(store, gen)` wraps AssessRecoverability; empty/fully-compensated generations are clean; irreversible receipts are never rewritten to rolled_back.

### 18.24 RuntimeSet (runtimeset.go)

- `RuntimeSet` tracks live resources bound to one snapshot generation (separate from the immutable snapshot; holds one EffectScope). `Add(closers...)` auto-generates `closer-<n>` IDs; a closer added to an already-closed set is closed immediately (the alternative — silently leaking it because the owner went away — is how sidecar processes outlive their session). `Close` is idempotent (most closers are not safe to invoke twice). `CloseIfGeneration(gen)` keeps stale cleanup from closing a newer runtime's resources.

### 18.25 Status documents (component_status.go)

- `ComponentStatus` JSON: `{id, state, generation, epoch?, error?, diagnostics?, updatedAt}`. `RuntimeStatus`: `{publishedGeneration, components, plan?, receipts?}`. `RuntimePlanView`: `{fromGeneration, toGeneration, added?, removed?, reloaded?, unchanged?, prefixChanged, providerChanged}` — a JSON projection of RuntimePlan without the live graph pointer (`PlanView`).

### 18.26 Contributor interface (contributor.go)

- `Contributor`: `Name() string` + `Contribute(ctx) ([]Contribution, error)`. Contribute must be deterministic for fixed underlying state — the Builder stamps per-contributor registration order, and determinism guarantees two builds over the same state produce the same snapshot. `ContributorFunc` requires an explicit name ("the closure passed at some call site" is useless in a conflict report).

### 18.27 Stale-generation rule (stale.go)

- `StaleGeneration(messageGen, publishedGen)` = both non-zero AND `messageGen < publishedGen`. Equal or newer generations are NOT stale: mid-activation UI/stream traffic for the generation about to be published must still be accepted.

### 18.28 Package doc (doc.go)

- The kernel models every capability (tools, skills, commands, prompts, hooks, MCP servers, providers, themes, interceptors, replacement slots) as a Contribution with explicit provenance assembled by a deterministic Builder into an immutable RuntimeSnapshot. RuntimeSnapshot stays configuration-only; live handles (processes, streams, watchers, goroutines) never enter the snapshot. Discovery stays in the existing packages; adapters.go maps resolved records onto Contributions. Winner rules are resolved once, identically for every caller: higher tier shadows lower for the same canonical ID, same-tier multi-source duplicates are hard conflicts instead of silent overrides, hooks/interceptors stay additive. Boot may opt into ConflictCollect (diagnostics + deterministic winner); native extensions keep ConflictFail.

## 19. Protocol artifact generation (protocolgen/)

### 19.1 Artifact set and determinism (generate.go)

- `Generate()` produces four deterministic artifacts WITHOUT reading committed outputs: `internal/ext/extension/protocol/schema.generated.json` (canonical schema bytes), `internal/ext/extension/protocol/schema_hash.generated.go` (const GeneratedSchemaHash), `docs/EXTENSION_PROTOCOL.generated.md` (machine-frozen method/event/limits/error index), `sdk/go/types_generated.go` (stdlib-only Go SDK DTO mirror). Order is stable as declared.
- Generate first validates the registry, builds the schema document, and asserts the canonical bytes equal the marshaled document (`canonical schema bytes do not match BuildSchemaDocument`); schema hash = `sha256:<hex>` of the canonical bytes.
- `Check(root, artifacts)` compares each artifact byte-for-byte with the committed file — drift fails with `generated artifact drift: <path>`. `Write` writes below a root (MkdirAll 0755, files 0644).
- The generated markdown always carries: protocol ID, major, schema path + hash, the stability sentence ("Within major v2 only optional fields, new enum values, and new methods may be added; existing required fields, directions, limits, error reasons, and semantics never change."), a methods table (Method | Direction | Class | Params | Result), the 17 intercept events, the four limits (frameBytes, externalizeFieldBytes, contentRefChunkBytes, contentRefObjectBytes), and the frozen error table (Reason | JSON-RPC code | Retryable | Message).

### 19.2 SDK type mirror (sdkgo.go)

- `walkSDKTypes` reflection-walks the frozen registry exactly like the schema builder (params types + non-notification result types) plus the roots no registry DTO references by name: the six host UI payload documents (UIStatusPayload, UICardPayload, UIFormPayload, UINotificationPayload, UIPanelPayload, UIViewPayload) and ProtocolErrorData. Anonymous structs, embedded fields, and named string types that are not frozen enums are rejected (`anonymous struct <t> is not a named wire DTO`, `embedded field <t> is not supported in wire DTOs`, `named string type <n> (<t>) is not a frozen enum`).
- Enum constant prefixes registered per type (e.g. InterceptEvent → Event..., ProviderChunkType → Chunk...); exceptions pin the established public API (`tool_call_args_delta` → `ChunkToolCallDelta`); initialisms ui/tui/acp/utf8 upper-cased. Identifier mangling splits on `_ . - /` and capitalizes each part.
- Emitted SDK surface: ProtocolID/ProtocolMajor/ProtocolVersion consts, the four frozen limits, method-name constants (`Method<Identifier>`, collision-checked), DomainErrorCode + frozenErrorSpecs table, then every walked enum and struct (fields with original JSON tags). `guardSDKSurfacePayloads` pins the surface-kind → payload-DTO convention: every UISurfaceKind value must have a matching `UI<Kind>Payload` type in the generated set, else `surface kind "<k>" has no payload DTO <t> in the generated set`.

## 20. Divergences and open decisions

Items where prose docs, source, and this inventory disagree, or where the source encodes behavior the docs do not state. None is an approved intentional break; the rule is source parity, recorded here so the Rust port does not silently drop them.

1. **Sixth decision `ask` is source-only.** The prose docs list five interceptor decisions (continue/block/replace/allow/deny), but enums.go freezes a sixth, `ask`, legal only for tighten-only runtimes at `permission.decision` (dispatch.go §15). The Rust enum must carry all six values and tests must cover the ask path; the docs simply under-report.
2. **dynamicTools tool specs.** `ToolSpec` (dto_lifecycle.go §12.5) lets a runtime advertise dynamic tool schemas at initialize beyond the manifest-declared names. The prose docs only describe statically declared `runtime.tools`. Rust must accept dynamic tool lists (manifest expectation governs legality, initialize supplies the specs).
3. **`agent.before_start` and session payload variants under-documented.** The docs list the 17 hook points but do not spell out the SessionPayload DTO serving the five session.* points or the agent.before_start payload shape; both are frozen in §12/§15 from source.
4. **Panel no-markdown asymmetry.** Most surfaces render their text via the safe Markdown renderer, but the panel payload is a composed tree of structured primitives (§12.11) without a markdown field. Per-kind payload shapes and limits (200/8/4000/200/64/128) are contract.
5. **nil-vs-empty array semantics in provider conversion.** providerconv converts between host and wire types; Go distinguishes nil slices (JSON `null`) from empty slices (JSON `[]`) and extension-side SDKs observe the difference. Rust serde must reproduce the exact wire behavior (Option<Vec> vs Vec mapped to null vs [] exactly where Go does).
6. **ConflictCollect is a boot-only policy.** The Builder defaults to ConflictFail; only legacy boot assembly opts into ConflictCollect (deterministic winner + shadowing diagnostics; malformed contributions and slot disputes still fail under both). Rust keeps both policies with the same defaults and the same fail-classes.
7. **Message-dedup retention is coupled to receipt eviction.** MessageSendGuard.ForgetReceipt fires from the ReceiptStore onEvict hook, so a resend-suppression key lives exactly as long as its receipt. The coupling is behavioral (the suppression window) and must be preserved, not reimplemented independently.
8. **Extension session state is an additive sidecar file.** `<session>.extensions.json` (§18.7) never reads or writes the session JSONL; a corrupt or missing store yields an empty store with no error (extension state must never crash session load). Atomicity (tmpfile+rename, 0644, trailing newline) and the 1 MiB drop-not-truncate cap are contract.
9. **tierRank: claude_compat(50) > codex_compat(40) > plugin(30).** Compat imports outrank native plugins in every shadow race (§18.18). Surprising but load-bearing for the Claude/Codex import paths; preserve exactly.
10. **Retention bounds are observable process-local contract.** 32 generations × 256 receipts, 8 MiB/entry and 32 MiB/owner file priors: eviction marks evidence truncated and recovery then refuses clean-rollback claims (§18.8/§18.17). `reasonix doctor runtime` output depends on these exact bounds.
